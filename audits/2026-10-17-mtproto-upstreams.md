# Сравнение MEKO и MTProxyL с 3x-ui — 17.10.2026

Проверены исходники, история изменений и совместимость существующей интеграции.
Это сравнение функциональности и целевая проверка, а не полный аудит двух внешних проектов.

## Зафиксированные версии источников

- [MEKO](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO/tree/fb724c6a9432333fe99c29b97520bad2370c6cd7): последний коммит 13 октября, исправление выбора порта установки Telemt.
- [MTProxyL](https://github.com/Liafanx/MTProxyL/tree/d3c98f7d4f4971822e90bba5068a977140c1b106): менеджер 1.7.5, панель 1.3.4; изменения по 15 октября.
- [Telemt 3.5.14](https://github.com/telemt/telemt/releases/tag/3.5.14): последний стабильный релиз, возвращённый GitHub API на момент проверки. 3x-ui загружает последний официальный стабильный бинарник при сборке.

## Исправлено в 3x-ui

1. **Неполная проверка iOS SYN-отпечатка.** Helper проверял тип TCP-опции MSS (2), но не её длину (4). Это слабее полного отпечатка nftables у MEKO и MTProxyL. Теперь оба backend, nftables и iptables/u32, проверяют байты `02 04`, чтобы некорректная опция не получала исключение из лимитера. Остальные поля отпечатка и параметры ограничения сохранены. Источники: [MEKO rules.sh](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO/blob/fb724c6a9432333fe99c29b97520bad2370c6cd7/data/rules.sh), [MTProxyL nft.sh](https://github.com/Liafanx/MTProxyL/blob/d3c98f7d4f4971822e90bba5068a977140c1b106/lib/nft.sh). Это усиление нашей интеграции; исходный u32-вариант MEKO тоже проверяет только тип MSS.
2. **iptables обходил правила основного firewall.** Helper ставит переход в свою цепочку первым в INPUT. Его `ACCEPT` окончательно разрешал SYN, даже если дальше INPUT запрещал этот порт или источник. Заменено на `RETURN`: прошедший лимитер SYN продолжает проверяться основным firewall, как уже происходило у nftables. Порты должны быть разрешены обычными правилами доступа сервера; helper ограничивает частоту SYN, а не открывает порты.

Регрессионные проверки запускают настоящий shell-helper с подставными командами firewall и анализируют сформированные команды. Они падали до исправлений и проходят после.

## Что уже учтено и что имеет смысл добавить отдельно

| Изменение внешних проектов | Состояние / вывод для 3x-ui |
| --- | --- |
| MEKO исключил SYN+ACK из SYN-лимитера 1 октября | Уже учтено: наша nft-маска включает ACK, FIN и RST; повторное изменение не требуется. [Коммит](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO/commit/38928e0a1c90283f0bc754bee007813e31de840b). |
| MEKO спрашивает порт при установке Telemt, проверяет занятость | Это относится к его установщику; 3x-ui задаёт порт в inbound и запускает свои sidecar-процессы. Переносить установщик MEKO не требуется. |
| MTProxyL 1.7.3 убрал обязательную привязку SYN-лимитера к IP | Наша цепочка уже работает по портам без фильтра destination IP; NAT и несколько адресов не требуют такого исправления. |
| MTProxyL 1.6.35 отключил nginx access.log по умолчанию | В генерируемом WEB-конфиге 3x-ui уже есть `access_log off`. |
| MTProxyL добавил перебор WEB carriers | В 3x-ui пока задан только `carrier = "https"`. Полезное отдельное расширение: выбор websocket-lanes / websocket / https с сохранением совместимости, проверкой версии движка и тестами nginx. Нынешний HTTPS остаётся поддерживаемым транспортом. |
| MTProxyL исправил донорский SOCKS5, DNS при смешанном IPv4/IPv6 и жизненный цикл туннеля | Исправления относятся к его менеджеру доноров и systemd-службам. В 3x-ui этот менеджер не используется; копирование shell-кода не исправляет нашу интеграцию. |
| MTProxyL поддерживает Caddy/HAProxy наряду с nginx для WEB/Selfmask | Отдельная функция выбора frontend; ошибки существующего nginx-backend из этого не следуют. |
| MTProxyL выпускает собственный Telemt с jitter повторных попыток ME, ограничением писателей, частичной деградацией DC и malloc_trim | Это патчи Rust-движка, не новые обязательные TOML-параметры. Набор в репозитории основан на Telemt 3.5.7. Автоматически заменять официальный 3.5.14 старой модифицированной базой не следует. `malloc_trim` относится только к glibc; сборки 3x-ui используют musl. Нужен отдельный сравнительный тест под нагрузкой, прежде чем менять поставщика движка. |

Подробности: [MTProxyL CHANGELOG](https://github.com/Liafanx/MTProxyL/blob/d3c98f7d4f4971822e90bba5068a977140c1b106/CHANGELOG.md), [описание патчей движка](https://github.com/Liafanx/MTProxyL/blob/d3c98f7d4f4971822e90bba5068a977140c1b106/engine/telemt/README.md).

## Выполненные проверки

- `go test -race ./internal/mtproto -count=1` — успешно.
- `golangci-lint run ./internal/mtproto/...` — 0 issues.
- `bash -n internal/Telemt/telemt-meko-fix.sh` и `git diff --check` — успешно.
- Скачан официальный musl-бинарник Telemt 3.5.14, архив проверен по опубликованному SHA-256.
- `TELEMT_TEST_BINARY=... go test ./internal/mtproto -run '^TestOfficialTelemtConfigAndReload$' -v -count=1` — успешно: запуск с конфигом 3x-ui, получение статистики, добавление пользователя, штатный reload и проверка нового пользователя через API.

Правила не применялись к firewall рабочего VDS. Проверка с официальным движком подтверждает конфиг и API reload, но не доступность Telegram у конкретного оператора и не эффективность обхода ограничений.

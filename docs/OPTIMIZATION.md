# Оптимизация DEV-сборок 3x-ui

Все оптимизации делаются в ветке `optimize`, затем проходят CI перед переносом в `main`.

## Неподвижные ограничения

- Единственный формат поставки. Разделения на Lite/Full нет.
- Поставка включает **панель, основное Hiddify-core, Telemt, Mieru (mita), TUIC-server** и все шесть GeoIP/GeoSite-файлов (основные, IR, RU).
- Дополнительные компоненты, устанавливаемые из настроек, остаются опциональными; их установка и доступность не меняются.
- Сохраняются текущие настройки, подписки, миграции, протоколы и возможность обновления DEV.
- Сокращать тестовое покрытие ради веса запрещено; оценивать размер исходников и установочного архива отдельно.

1. [x] Создать ветку `optimize` от DEV-main.
2. [x] Удалить npm-зависимости двух неиспользуемых локальных шрифтов без изменений CSS или внешних шрифтов.
3. [x] Убрать тестовый MSW worker из production-бандла (сохраняется в dev и тестах).
4. [x] Добавить автоматический отчёт о размере архива, распакованной поставки, отдельных протоколов, GeoIP/GeoSite и фронтенда; сохранить машинный JSON в GitHub Actions.
5. [x] Отклонять попадание production sourcemaps во фронтенд и проверять присутствие всех шести геобаз.
6. [x] Добавить `-trimpath` в сборки панели без изменения протоколов или линковки.
7. [ ] Снять размер DEV после сборки CI, сравнить с новой базой и определить бюджеты размеров.
8. [ ] Построить детализированный граф Go-импортов и выделить причины веса бинарника (без удаления необходимых сетевых библиотек).
9. [ ] Профилировать JS/CSS-чанки после Vite и уменьшить тяжёлые пути загрузки без ухудшения совместимости.
10. [ ] Рефакторить подтверждённые горячие пути Go/React и проверить CPU/RAM на тестовых сценариях.

Запуск отчёта вручную:

```bash
python3 tools/ci/size_report.py --frontend internal/web/dist
python3 tools/ci/size_report.py --package x-ui --archive x-ui-linux-amd64.tar.gz --frontend internal/web/dist --json size-report.json
python3 -m unittest discover -s tools/ci -p 'test_*.py'
```

Размеры указаны в десятичных МБ. `size_report.py` только читает файлы, не меняет поставку. Реальная экономия измеряется сравнением двух завершённых DEV-сборок, а не сопоставлением с архивами старых stable-релизов.

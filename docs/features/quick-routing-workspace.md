# Быстрая маршрутизация 3x-ui (Xray и sing-box)

Раздел **Маршрутизация** содержит общий быстрый мастер и сохраняет прежние
редакторы для сложных конфигураций.

## Быстрый мастер

1. Выберите условие: входящий порт/подключение, домен, IP/CIDR либо порт назначения.
2. Для доменов, IP и портов можно дополнительно ограничить правило конкретными входящими.
3. Выберите существующий исходящий тег (включая исходящие из подписок).
   Для sing-box доступно явное действие `reject`; в Xray для блокировки нужен
   реальный outbound с тегом `blocked`.
4. Нажмите **Создать маршрут**, затем общую кнопку сохранения конфигурации.

Пользовательские правила не переписываются. Мастер генерирует отдельные
управляемые правила `panel-quick:...` и при повторном выборе тех же условий
меняет цель существующего правила, не создавая дубликат. Цель также можно
поменять прямо в списке быстрых маршрутов. Включение и удаление меняют
только помеченные мастером правила.

Новое правило вставляется перед первым активным правилом, у которого нет
условий, если такое существует. Все другие правила (включая служебный
маршрут API, правила каталогов, балансировщиков и ранее созданные
маршруты) остаются в исходном порядке. **Важное правило:** движки
маршрутизации выбирают первое совпадение. Если другое правило с более
высоким приоритетом совпадает раньше быстрого маршрута, оно победит.
Для сложного переупорядочивания используйте расширенный редактор.

В мастер встроена лёгкая статическая проверка: отсутствующие исходящие
теги, дубликаты управляемых правил и правила без условий, которые
перекрывают последующие маршруты. Это предупреждения, а не полная
симуляция маршрутизации; реальную проверку Xray можно выполнить в
разделе **Тест маршрута**. У sing-box сохранение использует существующую
проверку конфигурации на сервере.

## Важные ограничения

- Быстрый мастер не меняет `route.final`, основной outbound Xray и не
  запускает автоматического применения конфигурации.
- Полный список старых правил, JSON, балансировщики и каталог остаются
  доступны отдельно.
- Сохранённые списки маршрутов, DNS, правила по процессу, клиенту и
  другие продвинутые условия редактируются в расширенном режиме.
- Домены принимаются как ASCII/Punycode; `*.example.com` преобразуется
  в правило по домену и поддоменам. Для точного совпадения предусмотрен
  отдельный режим.
- IP/CIDR и порты предварительно проверяются. Неизвестные IP-диапазоны,
  неподдерживаемые порты и отсутствующие теги не добавляются.
- Работа обоих движков зависит от настроек DNS и того, какие сведения о
  соединении доступны ядру. Мастер не гарантирует геолокацию, доступность
  сервера или обход сетевых ограничений.

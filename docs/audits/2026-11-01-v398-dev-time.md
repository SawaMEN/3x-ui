### HIGH (pre-existing since v3.9.8) — duplicate models in cross-DB migration

- Both `v3.9.8` and the audited main had duplicate `RoutingPreset` and
  `UserSession` entries in `internal/database/migrate_data.go:migrationModels()`.
- `MigrateData` and `copyAllModels` iterate that list and `copyTable`
  inserts rows without upsert. A second pass over a populated primary-key
  table causes duplicate-key failure; PostgreSQL truncation also receives
  repeated table names.
- `TestMigrationModelsMatchPanelModels` checked sets and therefore could
  not catch duplicates.
- Removed both duplicate entries in `f4a9fe7ca2ea27809180985cf931c31ecb821ecc`.
  Added `TestMigrationModelsHaveNoDuplicates` in
  `e6461244d2099dd8d49a0f8918385f462bd1f39f`.
- **Verification pending actual SQLite→PostgreSQL migration, export and CI.**
  Marked *pre-existing* rather than incorrectly attributing it to DEV.

### CI configuration coverage caveat

- `.github/workflows/protocol-build.yml` listens for pushes to `update`
  and manual dispatch. The available branch list included only `main` at
  audit start, so do not assume this workflow runs on all protocol changes.
- `.github/workflows/ci.yml` provides broad Go, frontend, PostgreSQL,
  race, security and shell checks, but passing unit tests alone does not
  verify live transports or release artefacts.

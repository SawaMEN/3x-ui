## Четыре исправления

1. После публикации candidate отказ Gateway/sidecar оставлял прежний runtime
   с новым файлом на диске. Публикация теперь предварительная до успеха runtime;
   при отказе возвращается applied snapshot либо прежний файл. При первом
   старте не принятый candidate удаляется. Ошибки восстановления возвращаются
   вместе с исходной. Учитывается и ошибка fsync каталога после rename.
2. Общий `SingBoxService.Start` не выбирал генератор Xray. Теперь используется
   собственный путь Xray, включая `run -test`. Регрессия проверяет корневые
   API/outbound-поля JSON, а не простое присутствие слова `protocol`.
3. Неудачный restart Xray запускал прежний applied snapshot даже для ранее
   остановленного процесса. Теперь работающий runtime восстанавливается, а
   остановленный остаётся остановленным. Recovery context ограничен.
4. Marker `standaloneCoreSelection` и `coreType` сохранялись отдельно. Отказ
   второй записи оставлял частичный результат. Standalone-выбор теперь сохраняет
   обе записи одной транзакцией; проверены новый и существующий marker.

Все четыре ошибки воспроизведены на worktree исходного `main@4aa74411` и на
предшествующем `update@239c20b7`. Первый исторический коммит появления каждой
проблемы этим этапом не bisect-ился. Локальные недочёты тестовой обвязки,
исправленные до публикации, не входят в число ошибок приложения.

## Оптимизация и удаление лишнего

Удалены повторные subprocess `version`: обычный process Start вызывает version
один раз вместо двух, MASQUE Validate — один раз вместо двух. Проверки version,
identity, tags и revision сохранены, включая проверку перед adoption. Это
измерение числа subprocess, не заявление о двукратном ускорении панели.

Общий helper Setting используется обычным сохранением и транзакцией выбора.
Синхронизация каталога и восстановление config-файла объединены вместо
повторяющихся блоков. Защитные тесты не выдаются за дополнительные найденные ошибки.

## Стенды и реальные данные

Нативные Ubuntu 24.04 amd64 и Ubuntu 24.04 arm64, Go 1.27.3. ARM-бинарники
исполнялись на ARM, не только кросс-компилировались. Закреплены archive SHA256:

- Hiddify-backed sing-box: static musl
  `sawamen-b310097c8e7a-338f0c9457a4-mask1-ciphers1-net62-sec1`,
  Actions run `41326858660` из этапа 2.
- Официальный Xray `v26.10.21`.
- Официальный upstream sing-box `v1.14.4`.

Для всех шести пар ядро×архитектура выполнены выбор/reopen БД, генерация и
native check, настоящий HTTP CONNECT с двусторонним TCP echo, повторный Start
с тем же RuntimeID, invalid JSON без остановки рабочего процесса, rollback
занятого порта с восстановлением данных, успешный restart, SIGKILL/crash
recovery, adoption новой копией менеджера и закрытие listener после Stop.
Сохранены actual binary hashes; latest не используется.

Через настоящий core-select handler на каждой архитектуре выполнены переходы
`sing-box → sing-box-upstream → xray → sing-box`: проверяются HTTP-трафик,
сохранённый выбор и отсутствие второго работающего ядра. Неверный executable
отвергается до остановки прежнего. Дополнительный wrapper делегирует настоящему
Xray version/native check, но инъецирует отказ запуска после остановки старого:
API возвращает отказ, прежние выбор и рабочий core восстанавливаются.

Реальный временный outbound probe выполняет HTTP-запрос своим процессом,
не останавливает production core и удаляет временную конфигурацию.
Auth/CSRF браузера относятся к этапам 9–10.

## Исправлено

- Убрана небезопасная совместимость: `install.sh` и `update.sh` больше не допускают отсутствующий `.sha256` даже для старого stable. Два входа используют одну и ту же функцию `verify_release_checksum`; отсутствие связи, неверный HTTP status, ошибка вычисления, некорректный hash и mismatch завершаются отказом **до остановки службы**. Политика SHA-256 защищает от повреждения артефактов при сравнении с опубликованным digest; это не независимая криптографическая подпись релиза.
- Проверка отклонённого архива перед штатной остановкой и сохранность ранее установленного service/DB добавлены в sandbox-тесты.
- Ошибки `systemctl daemon-reload/enable`, `rc-update add`, смены владельца, исполнения management script и permissions config теперь фатальны для транзакции и приводят к попытке rollback. Ранее они могли замалчиваться.
- Старую службу отключаем только если она была включена; не ломаем обновление изначально отключённой установки.
- Проверяются отказы регистрации службы после частичной замены бинарников.

## Ограничения

- Отрицательные shell-кейсы выполняются в песочнице, а не на production узле.
- Реальный clean-host smoke зависит от доступности опубликованного релиза и его sha256 sidecar. До успешного выполнения нет подтверждения реальной установки.
- Не заявляем полное покрытие всех дистрибутивов без их native smoke, ни восстановление после физической потери питания. Проверки физического узла и полный release gate остаются обязательными для финальной готовности.

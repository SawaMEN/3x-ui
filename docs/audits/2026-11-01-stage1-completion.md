## Что показал проход истории

В диапазоне 1 190 обычных и 66 merge-коммитов. Полный diff без определения
переименований содержит 1 020 добавлений, 850 изменений и 65 удалений.
Ещё 74 пути встречаются в истории, но не дают итогового изменения относительно
базы; для каждого сохранены происхождение и причина отсутствия в итоговом diff.

Для 12 слияний Git remerge-diff показывает ручное разрешение, для 54 — нет.
Для каждого из 12 сохранены diff, изменённые пути, контракт и этап исполнения:
Telemt WEB/MEKO, каскады протоколов, Snell, темы подписок/domain TLS/Mieru,
модели/API, HTTP bootstrap и объединение экранов обновления.
Это структурный разбор разрешений, не полное функциональное подтверждение
всех ветвей этих изменений.

Найдены 7 групп одинаковых stable patch ID. Инверсный проход patch ID не выявил
точных кандидатов отмены патча; это не исключает частичные или смысловые откаты.
Только 21 коммит подтверждён как изменение пробелов посредством `git diff -w`.
Остальные коммиты с названиями о форматировании/CI не исключены из аудита.

Все удаления получили решение: намеренное удаление функции, перенос,
объединение интерфейсов или замена теста/генератора. В частности, Discord удалён
как функция; активные routing categories Discord к этому удалению не относятся.
Старые Xray/TUIC реализации не служат основанием удалять действующие форматы,
миграционные читатели и переходы sidecar. Для таких случаев назначены проверки
совместимости в соответствующих этапах.

## Карта контрактов и её границы

В AST/diff-индексе 5 186 изменённых деклараций. Для 4 036 найдены статические
тестовые ссылки либо compile-time маршрут. Это кандидаты: совпадение имени,
вызов или присутствие assertion в тесте не доказывают нужную семантику.
Для 1 150 ссылок не найдено; для каждой заведена задача с идентификатором,
исходным символом, ожидаемым контрактом и маршрутом проектирования регрессии.
Отсутствие статической ссылки само по себе не является найденной ошибкой.

Каждый путь связан со спецификацией контракта, владельцем-этапом, командой
инспекции и способом исполнения либо объяснённым исключением. Для удалённых
пакетов указан разбор замены, а не неработающая команда `go test` старого каталога.
Генерация проверяется от источника истины; документация и переводы — проверками
примеров, ключей, ссылок и отображения. Число деклараций не равно числу
пользовательских изменений и не заявляется как полное семантическое покрытие.

Перед закрытием соответствующего этапа необходимо проверить достаточность
assertions, уточнить конкретные входы и наблюдаемый результат и выполнить тесты
без обязательных SKIP. Очередь этих действий сохранена, а не отмечена пройденной.

При обновлении копии до проверенного SHA сохранены все прежние пользовательские

добавлены 6 записей истории миграций и 4 пустые служебные таблицы. Остальные
существующие значения совпадают. Повторное открытие логически идентично первому;
`integrity_check` — `ok`, нарушений FK нет. Сохранены обе базы, дампы, снимки
строк и контрольные суммы, а не только количества записей.

Это fixture хранения/миграции, а не подтверждение реального трафика всех
протоколов. Перенос путей сертификатов, handshake, SQLite↔PostgreSQL,

## Исправления и оптимизация в update

Ранее опубликованные изменения tail/logger/runtime дополнены исправлением
несовместимости явных legacy TLS suites с закреплённым ядром. Панель принимала
название `TLS_RSA_WITH_AES_128_GCM_SHA256`, но native constructor его отвергал.
Overlay теперь разрешает явно выбранные имена из обоих списков Go, сохраняя
неизменными стандартные defaults и отказ для неизвестных имён. Общий helper
заменяет три повторявшихся поиска; наборы по умолчанию не расширяются.

Закреплённое ядро собрано локально с overlays. Его native TLS-тесты и все
конструкторные проверки `TestPinnedBinaryChecksGeneratedConfigurations`
прошли без пропусков. Собран production panel с `vcs.modified=false` для
`5d30b45c`; идентичности и SHA256 сохранены. Подробности и измерения оптимизаций:

- [Tail](./2026-11-01-tail-optimization.md)
- [Logger](./2026-11-01-logger-optimization.md)
- [Runtime](./2026-11-01-runtime-cleanup.md)
- [Явные TLS suites](./2026-11-01-explicit-tls-ciphers.md)

Отдельно заморожен внешний release ядра
`sawamen-3d4ee155c924-244e333149ec-panel9` для amd64/arm64. Он не эквивалентен
сборке с закреплёнными overlays: текущие пробы отвергаются для `final_mask` и
legacy suites. Это открытая проверка выбора/обновления ядра в этапах 5/11;
внешний release нельзя использовать как доказанную замену проверенной сборки.

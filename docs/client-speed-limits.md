# Ограничение скорости клиента

В форме создания или редактирования клиента включите «Ограничение скорости трафика» и укажите загрузку и отдачу в Мбит/с. По умолчанию функция выключена. Ноль оставляет соответствующее направление без ограничения; при включении хотя бы одно значение должно быть положительным. Допустимые значения — целые числа от 0 до 100000.

Лимит действует на сервере, не требует изменения клиентского приложения и делится между TCP- и UDP-соединениями одной клиентской записи, включая подключения через разные входящие. Другие клиенты используют собственные лимиты или работают без ограничения. Начальный кратковременный всплеск допускается в пределах 64 КиБ на направление. Внутренняя обработка DNS ядром сохраняется отдельно от ограничения проксируемых соединений.

Поддерживаются VMess, VLESS, HTTP, Mixed, Trojan, Shadowsocks, Hysteria2, TUIC, NaiveProxy, AnyTLS, Snell и ShadowTLS. Для WireGuard, AmneziaWG, MASQUE, MTProto и внешних протокольных служб включённый лимит отклоняется: им нужен отдельный механизм идентификации/ограничения, а не фиктивное поле в панели. При ограничениях Hysteria2 используется встроенное ядро, сохраняющее идентификацию пользователя.

Ограничение общее для соединений клиента на **одном сервере**. На удалённых нодах нужно установить эту же версию панели; каждая нода применяет свой лимит независимо. Это не распределённая квота скорости на весь кластер. Внешние ссылки в подписке также не управляются этим сервером.

При изменении плана ограничений текущие соединения ограничиваемых клиентов закрываются и переподключаются. Маршрутизация, блокирующие правила и выбор исходящего подключения сохраняются; повторный проход через ядро не учитывается как дополнительный клиентский трафик.

Только для ограничиваемых клиентов добавляется локальный SOCKS-проход через ограничитель в процессе панели. Порты 15879 и 15880 используются на 127.0.0.1 и защищены случайным паролем процесса. Конфликт порта отклоняет применение конфигурации; при ошибке запуска ядра восстанавливается прежний план. Когда ограничений нет, дополнительный слушатель не запускается.

В API клиент принимает объект `speedLimit`:

```json
{"enabled": true, "uploadMbps": 5, "downloadMbps": 20}
```

`enabled: false` отключает ограничение, сохраняя значения для следующего включения. Отсутствие объекта в старом запросе сохраняет существующий лимит. Объект входит в экспорт/импорт клиентов, настройки входящих и синхронизацию нод.

Проверки: `go test -race ./internal/clientlimit`; серверные тесты `TestClientSpeedLimit*`. Для проверки с настоящим ядром задайте `HIDDIFY_CONFIG_CHECK_BINARY=/absolute/path/hiddify-core` и запустите `go test ./internal/web/service -run TestClientSpeedLimit -v`.

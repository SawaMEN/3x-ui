# Домены и TLS — управление и эксплуатация

Панель **Настройки → Домены и TLS** управляет локальным HTTP/HTTPS-шлюзом, сертификатами и SNI подключённых нод. Настройки организованы в четыре раздела: **Домены**, **Сертификаты**, **SNI и ноды**, **Настройки**. Обычные действия доступны без открытия расширенного редактора.

## Запуск домена

1. Добавьте имя домена, выберите назначение и режим TLS.
2. Введите адрес электронной почты ACME и примите условия центра сертификации, если нужен автоматический TLS.
3. Нажмите «Проверить готовность»: панель проверяет конфигурацию, конфликтующие локальные порты, существующие сертификаты, DNS и состояние подключённых нод.
4. Просмотрите предупреждения и выберите «Сохранить и применить». Только действие применения меняет работающий шлюз.

**HTTP-01:** публичный TCP 80 должен вести к этому шлюзу. Если подключены другие ноды-наблюдатели, проверка готовности запрашивает у них независимый доступ к одноразовому HTTP-01 URL. Для нового домена, когда TCP 80 свободен, панель может кратковременно открыть только этот URL и затем закрыть обработчик. Если порт занят чужим сервисом, независимую проверку выполнить нельзя без изменения его конфигурации. Отсутствие подтверждения не считается доказательством отсутствия публичного доступа: NAT, Cloudflare и файрволл хостера настраиваются отдельно.

Проверка DNS-IP сравнивает записи с явно настроенным публичным IP listener, а для удалённых SNI — с публичным IP соответствующей ноды, если IP указан непосредственно. Сопоставление является диагностикой: CDN, reverse-proxy и NAT могут закономерно давать другие адреса. Проверка перед применением не гарантирует, что DNS или правила файрволла не изменятся позднее.

## Автоматический TLS: HTTP-01 или DNS-01

В настройках доступны:
- **Обычный TLS:** CertMagic использует HTTP-01/TLS-ALPN-01, включая штатное продление, журнал событий и временные правила локального файрволла.
- **Cloudflare DNS-01:** DNS-зона, 32-символьный Zone ID, write-only API-токен.
- **DigitalOcean DNS-01:** DNS-зона и write-only API-токен; Zone ID не требуется.

DNS-01 позволяет выпускать wildcard-сертификаты, например `*.example.org`, без публичного TCP 80. Зона должна содержать запрошенный домен. В режиме DNS-01 все автоматические сертификаты шлюза используют только DNS-подтверждение; входящие порты для подтверждения не открываются. Поддерживается задержка распространения 0–180 секунд и ограниченный срок ожидания. API-провайдеры повторяют временно неудачные запросы максимум три раза с задержками и отказываются создавать записи за пределами `_acme-challenge`. Удаляются только записи с идентификаторами, полученными при создании текущей ACME-операции. CertMagic дополнительно применяет собственные правила повтора и ограничения ACME.

**Минимальные полномочия:** для Cloudflare используйте токен с DNS:Edit для одной нужной зоны и необходимыми разрешениями чтения зоны; для DigitalOcean — токен с минимальными доступными полномочиями на управление DNS выбранного домена. Не используйте глобальные API-ключи, если можно ограничить область доступа.

Токены хранятся **отдельно от конфигурации шлюза и не возвращаются в ответах API**. По умолчанию сервер сохраняет их в файлах с правами 0600 в каталоге базы данных:
- `domain-cloudflare-dns-token`
- `domain-digitalocean-dns-token`

Вместо файлов допускаются переменные окружения `X_UI_CLOUDFLARE_DNS_TOKEN` и `X_UI_DIGITALOCEAN_DNS_TOKEN` (они имеют приоритет). Интерфейс показывает только факт наличия токена и его источник; сохранённый токен нельзя прочитать обратно. После изменения провайдера или токена примените настройки шлюза.

## Сертификаты и ноды

Единый реестр показывает имя и SAN, издателя, владельца, срок, способ проверки, состояние и менеджер сертификата. Для локальных acme.sh/Certbot доступно ограниченное штатное продление без shell; нативные renewal-hooks открывают необходимые порты временно. CertMagic обслуживает собственные сертификаты самостоятельно; для локального сертификата, приближающегося к сроку истечения, можно инициировать **непринудительную** проверку продления. На удалённые ноды команды продления не отправляются.

Удалённые ноды читаются через существующий защищённый API с ограниченными временем, числом запросов и параллелизмом. Центральная панель получает **только метаданные сертификатов и владельцев**; абсолютные пути и закрытые ключи не копируются с нод. Временное применение чужого пути в локальной конфигурации запрещено. При проверке общего SNI локально оцениваются сертификат и публичные адреса той ноды, которой он принадлежит. Управлять сертификатом следует на его собственном сервере.

API-токен подключения ноды допускается для чтения и диагностики, но не для изменения токенов DNS, конфигурации доменного шлюза или ручного продления: эти операции требуют интерактивной сессии администратора панели.

## Мониторинг и история

Сервер периодически проверяет локальные сертификаты и сертификаты доступных подключённых нод, не читая их приватные файлы. Отслеживаются ошибки, истечение менее чем через 30 дней, истёкшие сертификаты и восстановление. Уведомления публикуются **при смене состояния** через включённые администратором каналы Telegram/email. Записи в журнале ограничены 250 событиями; удалённые события содержат ID ноды. Недоступность ноды не приравнивается автоматически к успешному восстановлению её сертификатов.

Состояние DNS, облачного файрволла и NAT может измениться после проверки; автоматическое сканирование не подменяет проверку доступности у владельца инфраструктуры.

## Статус проверки

Функциональная реализация собрана в ветке `domen`. По запросу владельца проекта тесты и ожидание GitHub Actions CI в этом этапе **намеренно пропущены**. Это не равнозначно подтверждённой успешной сборке или готовности к промышленному внедрению: перед развёртыванием требуются обычная проверка компиляции, сборки интерфейса, автоматические тесты и ограниченный пилот на тестовом домене.

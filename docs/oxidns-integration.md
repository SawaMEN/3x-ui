# Собственный DNS на OxiDNS

3x-ui использует официальный [OxiDNS](https://github.com/svenshi/oxidns) как управляемую DNS-службу рядом с форком sing-box. Изменять OxiDNS или устанавливать его WebUI не требуется.

## Быстрая настройка

1. Откройте **sing-box → DNS**. Блок **OxiDNS — собственный DNS** виден, даже если компонент ещё не установлен.
2. Выберите готовый сценарий: **Только для sing-box** (рекомендуется), **Sing-box + DoH для устройств** или **Все протоколы**. Нужные переключатели будут выставлены автоматически.
3. Нажмите **Установить OxiDNS** здесь или установите компонент в разделе **Обновления пакетов и ядер Linux**. Установка не включает DNS и сохраняет выбранные параметры.
4. Выберите DNS-провайдера (Quad9, Cloudflare, AdGuard, Google или Яндекс) и нажмите **Включить DNS**. Для внешних протоколов дополнительно укажите домен с действующим сертификатом панели.

До установки непустого исполняемого файла включение блокируется и в интерфейсе, и на сервере. Ошибка скачивания оставляет DNS выключенным. После установки панель создаст конфигурацию, запустит службу, проверит настоящий DNS-запрос и подключит OxiDNS к sing-box. Дальнейшие изменения применяются кнопкой **Сохранить и применить**; повторный запуск — **Перезапустить DNS**.

При настройке не требуется домен или сертификат, если DNS используется локально в sing-box. Существующие пользовательские DNS-правила не удаляются: OxiDNS становится DNS по умолчанию, отдельные правила продолжают действовать. Ошибки запуска показываются непосредственно на экране.

Для других устройств разверните **Дополнительные настройки: DoH, DoT, DoQ и HTTP/3**. Там есть переключатели каждого протокола, поля домена и портов, предупреждения о конфликтах и проверка формата домена. Настройки публичных слушателей по умолчанию выключены.

После запуска здесь же доступны готовые адреса для копирования, проверка реального DNS-запроса, обновление состояния и выключение. Проверка новой версии, обновление OxiDNS, просмотр последних 80 строк журнала службы и полное удаление с подтверждением собраны под раскрывающимся разделом **Обслуживание и диагностика OxiDNS**, чтобы не перегружать основной экран. При выключении настройки сохраняются, при удалении — очищаются.

Локальный DNS слушает UDP и TCP на 127.0.0.1:15353; доступ из интернета к этому порту не открывается. Для ускорения повторных запросов панель автоматически включает TTL-кэш OxiDNS (4096 записей, максимальный TTL 10 минут).

### Публичные DoH, DoT, DoQ и HTTP/3

В настройках можно независимо включить **DoH** (HTTP/1.1 и HTTP/2, TCP/8443 по умолчанию), **DoT** (TCP/853), **DoQ** (UDP/853). Для DoH дополнительно доступен **HTTP/3 (H3)** на том же порту через UDP с оповещением Alt-Svc. OxiDNS самостоятельно создаёт соответствующие HTTP/TCP/QUIC-серверы, используя общую DNS-политику и существующий TLS-сертификат панели. Никаких правок YAML не требуется.

DoT и DoQ могут оба использовать 853, поскольку это разные транспортные протоколы. Если DoH и DoT используют один TCP-порт либо DoH/H3 и DoQ — один UDP-порт, интерфейс и сервер отклонят конфликт. Системный порт 15353 зарезервирован под локальный DNS.

После включения панель покажет готовые адреса DoH, DoT и DoQ. Для DoT и DoQ сертификат нужен так же, как для DoH. Для всех публичных режимов потребуется направить домен на сервер и самостоятельно открыть соответствующие TCP/UDP-порты. Локальный DNS по UDP/TCP остаётся доступен без этих требований.

### Публичный DoH

Для использования DNS с других устройств включите DoH, DoT или DoQ. После этого появятся поля домена и портов активных протоколов. Нужны домен и действительный TLS-сертификат, **уже настроенный в панели**, подходящий этому домену. Интерфейс не позволит применить DoH с пустым доменом или некорректным портом. Нажмите «Включить DNS» или «Сохранить и применить». После запуска появится адрес DoH для копирования. По умолчанию DoH доступен по адресу:

https://dns.example.com:8443/dns-query

Для обычного адреса без порта можно выбрать 443 в дополнительных настройках, только если он свободен. На серверах с REALITY, XHTTP или другим HTTPS-сервисом порт 443 часто занят. Откройте выбранный HTTPS-порт в межсетевом экране и направьте домен на сервер.

Автоматического заказа DNS-домена, выпуска TLS-сертификата, проброса портов и настройки доменной зоны эта интеграция пока не выполняет. Для локального DNS ничего из этого не требуется.

## Установка и обновления

Откройте **Настройки → Обновления пакетов и ядер Linux**. В списке дополнительных компонентов будет **OxiDNS**.

- **Установить**: скачать проверенный официальный бинарник и зарегистрировать systemd-службу без запуска. После установки откройте **Быстрый запуск DNS** и нажмите **Включить DNS**.
- **Обновить**: скачать новую версию с проверкой SHA-256, сохранив настройки DNS и перезапустив службу, если она была включена.
- **Удалить**: сначала отключить OxiDNS в sing-box и вернуть прежнюю конфигурацию, затем остановить и отключить службу и удалить файлы компонента. Карточка быстрого запуска остаётся в sing-box → DNS, чтобы OxiDNS при необходимости можно было установить заново одним нажатием.
- **Обновить пакеты**: обновлять только ранее установленные компоненты, включая OxiDNS, если доступна новая версия.

Релизы скачиваются с svenshi/oxidns через GitHub Releases. Файл проверяется по SHA-256, опубликованному в GitHub API. Если после обновления новая служба не запускается или не открывает локальный порт, старый бинарник восстанавливается.

## Поддерживаемые системы и ограничения

Автоматическая установка рассчитана на **Linux x86_64 и ARM64 с systemd**, при запуске панели от root. Для Docker и остальных систем нужен отдельный менеджер контейнеров/служб.

При отключении OxiDNS его сохранённая конфигурация не удаляется; при удалении пакета служебная конфигурация удаляется. Управление и статус доступны только через авторизованный API 3x-ui; самостоятельный WebUI OxiDNS на открытом порту не запускается.

Публичный DoH является резолвером. Не открывайте сервис публично без понимания возможных злоупотреблений и сетевых ограничений. Для крупных развертываний дополнительно необходимы ограничения нагрузки и мониторинг. OxiDNS не заменяет авторитативный DNS-хостинг доменной зоны.

## API

Настройки DNS и кнопки обновлений обращаются к авторизованным маршрутам 3x-ui:

- GET /panel/api/oxidns/status (с ?check=true проверяет последний официальный релиз);
- GET /panel/api/oxidns/logs (последние 80 записей журнала выделенной systemd-службы);
- POST /panel/api/oxidns/setup и /disable (setup требует предварительной установки компонента);
- POST /panel/api/oxidns/install, /update и /remove.

Код управления службой находится в internal/oxidns/; интеграция sing-box — в internal/web/service/singbox.go. Поля управления OxiDNS не сохраняются в пользовательском JSON sing-box.

## Google и Яндекс DNS

Google Public DNS подключается по DoT (dns.google:853, bootstrap 8.8.8.8).
Яндекс DNS использует официальные режимы с шифрованием DoT:

- **Базовый:** common.dot.dns.yandex.net:853, bootstrap 77.88.8.8;
- **Безопасный:** safe.dot.dns.yandex.net:853, bootstrap 77.88.8.88;
- **Семейный:** family.dot.dns.yandex.net:853, bootstrap 77.88.8.7.

Выбранный режим применяется после нажатия «Сохранить и применить», остальная конфигурация sing-box сохраняется. Уровень фильтрации определяется самими DNS-провайдерами, а не программой 3x-ui.

Источники: https://dns.yandex.ru/ и https://developers.google.com/speed/public-dns/docs/dns-over-tls

## Проверка работы DNS

На странице sing-box → DNS нажмите «Проверить DNS-запрос». Панель выполнит настоящий запрос имени example.com через локальный DNS и проверит наличие IP-адреса, а не только запущенный процесс. При недоступности зашифрованного DNS-провайдера (например, блокировке TCP-порта 853) панель покажет объяснение и предложит проверить сеть либо выбрать другого провайдера. Во время включения службы такая проверка также выполняется автоматически: при неудаче конфигурация откатывается.

## Восстановление после ошибки

Если запуск OxiDNS завершился ошибкой, панель восстанавливает предыдущее состояние службы. Когда DNS был выключен, наличие ранее созданного config.yaml не приводит к повторному запуску службы. Откат системных операций выполняется в отдельном ограниченном по времени контексте и сообщает об ошибках восстановления.

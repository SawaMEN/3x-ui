# Собственный DNS на OxiDNS

3x-ui использует официальный [OxiDNS](https://github.com/svenshi/oxidns) как управляемую DNS-службу рядом с форком sing-box. Изменять OxiDNS или устанавливать его WebUI не требуется.

## Быстрая настройка

1. Откройте **sing-box → DNS → Собственный DNS — OxiDNS**.
2. Выберите провайдера (по умолчанию Quad9). Доступны Google Public DNS, Яндекс DNS (Базовый, Безопасный и Семейный), Cloudflare и AdGuard DNS.
3. Оставьте включённым «Использовать этот DNS в sing-box».
4. Нажмите **Установить и включить**.

Панель скачает официальный релиз, проверит контрольную сумму, установит службу systemd, создаст конфигурацию, запустит OxiDNS и обновит DNS-конфигурацию sing-box. Пользовательские DNS-серверы и правила sing-box не удаляются: управляемый OxiDNS становится DNS по умолчанию, а отдельные правила продолжают действовать.

Локальный DNS слушает UDP и TCP на 127.0.0.1:15353; доступ из интернета к этому порту не открывается. Для ускорения повторных запросов панель автоматически включает TTL-кэш OxiDNS (4096 записей, максимальный TTL 10 минут).

### Публичный DoH

Для использования DNS с других устройств включите переключатель «Включить собственный DoH». Потребуются домен и действительный TLS-сертификат, **уже настроенный в панели**, подходящий этому домену. Нажмите «Сохранить и применить». По умолчанию DoH доступен по адресу:

https://dns.example.com:8443/dns-query

Для обычного адреса без порта можно выбрать 443 в дополнительных настройках, только если он свободен. На серверах с REALITY, XHTTP или другим HTTPS-сервисом порт 443 часто занят. Откройте выбранный HTTPS-порт в межсетевом экране и направьте домен на сервер.

Автоматического заказа DNS-домена, выпуска TLS-сертификата, проброса портов и настройки доменной зоны эта интеграция пока не выполняет. Для локального DNS ничего из этого не требуется.

## Установка и обновления

Откройте **Настройки → Обновления пакетов и ядер Linux**. В списке дополнительных компонентов будет **OxiDNS**.

- **Установить**: скачать проверенный официальный бинарник и зарегистрировать systemd-службу без запуска. После установки появляется кнопка **Создать DNS**, которая открывает sing-box → DNS. Пользователь выбирает Google, Яндекс или другого провайдера и нажимает «Создать и включить DNS»; настройка и запуск выполняются автоматически.
- **Обновить**: скачать новую версию с проверкой SHA-256, сохранив настройки DNS и перезапустив службу, если она была включена.
- **Удалить**: сначала отключить DNS в sing-box и вернуть его прежнюю конфигурацию, затем остановить и отключить службу, удалить бинарник, конфигурацию, кэш и файл сохранённых настроек OxiDNS. После удаления карточка OxiDNS и кнопки создания/проверки собственного DNS исчезают из sing-box → DNS (остаются обычные встроенные DNS-настройки sing-box).
- **Обновить пакеты**: обновлять только ранее установленные компоненты, включая OxiDNS, если доступна новая версия.

Релизы скачиваются с svenshi/oxidns через GitHub Releases. Файл проверяется по SHA-256, опубликованному в GitHub API. Если после обновления новая служба не запускается или не открывает локальный порт, старый бинарник восстанавливается.

## Поддерживаемые системы и ограничения

Автоматическая установка рассчитана на **Linux x86_64 и ARM64 с systemd**, при запуске панели от root. Для Docker и остальных систем нужен отдельный менеджер контейнеров/служб.

При отключении OxiDNS его сохранённая конфигурация не удаляется; при удалении пакета служебная конфигурация удаляется. Управление и статус доступны только через авторизованный API 3x-ui; самостоятельный WebUI OxiDNS на открытом порту не запускается.

Публичный DoH является резолвером. Не открывайте сервис публично без понимания возможных злоупотреблений и сетевых ограничений. Для крупных развертываний дополнительно необходимы ограничения нагрузки и мониторинг. OxiDNS не заменяет авторитативный DNS-хостинг доменной зоны.

## API

Настройки DNS и кнопки обновлений обращаются к авторизованным маршрутам 3x-ui:

- GET /panel/api/oxidns/status (с ?check=true проверяет последний официальный релиз);
- POST /panel/api/oxidns/setup и /disable;
- POST /panel/api/oxidns/install, /update и /remove.

Код управления службой находится в internal/oxidns/; интеграция sing-box — в internal/web/service/singbox.go. Поля управления OxiDNS не сохраняются в пользовательском JSON sing-box.

## Google и Яндекс DNS

Google Public DNS подключается по DoT (dns.google:853, bootstrap 8.8.8.8).
Яндекс DNS использует официальные режимы с шифрованием DoT:
- **Базовый:** common.dot.dns.yandex.net:853, bootstrap 77.88.8.8;
- **Безопасный:** safe.dot.dns.yandex.net:853, bootstrap 77.88.8.88;
- **Семейный:** family.dot.dns.yandex.net:853, bootstrap 77.88.8.7.

Выбранный режим применяется после нажатия «Сохранить и применить», остальная конфигурация sing-box сохраняется. Уровень фильтрации определяется самими DNS-провайдерами, а не программой 3x-ui.

Источники: https://dns.yandex.ru/ и https://developers.google.com/speed/public-dns/docs/dns-over-tls

## Проверка работы DNS

На странице sing-box → DNS нажмите «Проверить работу DNS». Панель выполнит настоящий запрос имени example.com через локальный DNS и проверит наличие IP-адреса, а не только запущенный процесс. При недоступности зашифрованного DNS-провайдера (например, блокировке TCP-порта 853) панель покажет объяснение и предложит проверить сеть либо выбрать другого провайдера. Во время включения службы такая проверка также выполняется автоматически: при неудаче конфигурация откатывается.

## Восстановление после ошибки

Если запуск OxiDNS завершился ошибкой, панель восстанавливает предыдущее состояние службы. Когда DNS был выключен, наличие ранее созданного config.yaml не приводит к повторному запуску службы. Откат системных операций выполняется в отдельном ограниченном по времени контексте и сообщает об ошибках восстановления.

# Собственный DNS на OxiDNS

3x-ui использует официальный [OxiDNS](https://github.com/svenshi/oxidns) как управляемую DNS-службу рядом с форком sing-box. Изменять OxiDNS или устанавливать его WebUI не требуется.

## Быстрая настройка

Установка и конфигурация разделены:

1. Откройте **Настройки → Системные пакеты и ядро Linux → OxiDNS** и нажмите **Установить OxiDNS**. Здесь выполняются **только установка, обновление и удаление** программ. Установка не запускает DNS.
2. Откройте **sing-box → DNS → OxiDNS — собственный DNS**. Если пакет не установлен, вместо настроек отображается лишь пояснение, где его установить. Кнопок установки, обновления или удаления на этом экране нет.
3. **Шаг 1 — Для чего нужен DNS?** Для VPN выберите **Для VPN / sing-box** (вариант по умолчанию); для телефона и браузера — **Для телефона и браузера (DoH)**. Режим **Все протоколы (опытным)** открывает DoH, DoT и DoQ.
4. **Шаг 2 — Откуда получать DNS-ответы?** Выберите внешний защищённый провайдер (Quad9, Cloudflare, AdGuard, Google или Яндекс). OxiDNS разрешает домены через него и кэширует ответы; это не хостинг авторитативных DNS-записей.
5. **Шаг 3 — Создайте и запустите DNS**: нажмите **Создать и включить DNS**. Панель генерирует конфигурацию, запускает OxiDNS, проверяет реальный DNS-запрос и автоматически использует OxiDNS в sing-box, если выбран соответствующий режим. Повторные изменения применяются кнопкой **Сохранить и применить**.

**Для VPN через sing-box домен, TLS-сертификат и настройка firewall не нужны.** OxiDNS работает локально на 127.0.0.1:15353; существующие пользовательские DNS-правила sing-box сохраняются. TTL-кэш использует 4096 записей и TTL не выше 10 минут.

**Для подключения телефона или браузера напрямую** нужен DNS-поддомен, указывающий на IP сервера, действующий сертификат для этого имени и открытые порты. Поддомен не обязан совпадать с адресом панели: можно использовать отдельную пару файлов TLS-сертификата и ключа. Выбор сценария DoH автоматически показывает расширенные параметры. Панель настраивает DNS-службу и формирует адрес подключения, но **не регистрирует домен, не выпускает TLS-сертификат, не создаёт DNS-записи и не меняет firewall**. Без этих предпосылок публичный режим не заработает. Локальный режим не имеет этих требований.

На странице DNS доступны включение, выключение, изменение настроек, проверка DNS-запроса, готовые адреса для копирования и журнал службы в разделе **Диагностика OxiDNS**. Жизненным циклом бинарника управляют только в системных пакетах.

### Публичные DoH, DoT, DoQ и HTTP/3

В настройках можно независимо включить **DoH** (HTTP/1.1 и HTTP/2, TCP/8443 по умолчанию), **DoT** (TCP/853), **DoQ** (UDP/853). Для DoH дополнительно доступен **HTTP/3 (H3)** на том же порту через UDP с оповещением Alt-Svc. OxiDNS самостоятельно создаёт соответствующие HTTP/TCP/QUIC-серверы, используя общую DNS-политику и выбранный TLS-сертификат: сертификат панели по умолчанию либо отдельный для DNS. Никаких правок YAML не требуется.

DoT и DoQ могут оба использовать 853, поскольку это разные транспортные протоколы. Если DoH и DoT используют один TCP-порт либо DoH/H3 и DoQ — один UDP-порт, интерфейс и сервер отклонят конфликт. Системный порт 15353 зарезервирован под локальный DNS.

После включения панель покажет готовые адреса DoH, DoT и DoQ. Для DoT и DoQ сертификат нужен так же, как для DoH. Для всех публичных режимов потребуется направить домен на сервер и самостоятельно открыть соответствующие TCP/UDP-порты. Локальный DNS по UDP/TCP остаётся доступен без этих требований.

### Публичный DoH

Для использования DNS с других устройств включите DoH, DoT или DoQ. Панель покажет мастер настройки другого поддомена, например `dns.other-domain.net`, даже если панель работает на `panel.example.com`.

1. **Введите полное DNS-имя** `dns.other-domain.net` в поле «Домен защищённого DNS».
2. **Добавьте A-запись** `dns.other-domain.net` на публичный IPv4 сервера (и AAAA на публичный IPv6, если используется). Отключите проксирование DNS-записи у провайдера, если оно мешает прямому соединению, например Cloudflare DNS only.
3. **Подготовьте TLS-сертификат** для `dns.other-domain.net` или подходящий wildcard. Если уже настроенный сертификат панели покрывает это имя, дополнительные поля можно оставить пустыми. Иначе в «Дополнительные настройки» укажите **абсолютные пути** к отдельным PEM-файлам сертификата и ключа, например `/etc/letsencrypt/live/dns.other-domain.net/fullchain.pem` и `/etc/letsencrypt/live/dns.other-domain.net/privkey.pem`. Служба OxiDNS должна иметь доступ к файлам.
4. **Разрешите порты** из подсказки на экране (для DoH по умолчанию TCP/8443, для DoT TCP/853, для DoQ UDP/853, для HTTP/3 ещё UDP на порту DoH). Не занимайте порт, который используется другим сервисом.
5. Нажмите **«Проверить DNS-домен и сертификат»**. Панель проверит выбранные файлы, срок действия сертификата и соответствие DNS-имени, не перезапуская службу. Эта проверка **не подтверждает**, что записи A/AAAA уже указывают на ваш сервер или что порты доступны из интернета.
6. Нажмите **«Создать и включить DNS»** (или «Сохранить и применить»). Сервер повторно проверит сертификат до запуска и вернёт понятную ошибку, если он не подходит. После запуска готовый адрес появится для копирования.

По умолчанию DoH доступен по адресу:

https://dns.example.com:8443/dns-query

Для обычного адреса без порта можно выбрать 443 в дополнительных настройках, только если он свободен. На серверах с REALITY, XHTTP или другим HTTPS-сервисом порт 443 часто занят. Откройте выбранный HTTPS-порт в межсетевом экране и направьте домен на сервер.

Автоматического заказа DNS-домена, выпуска TLS-сертификата, проброса портов и настройки доменной зоны эта интеграция пока не выполняет. Для локального DNS ничего из этого не требуется.

## Установка и обновления

Откройте **Настройки → Системные пакеты и ядро Linux**. В карточке OxiDNS доступны только операции с установленным пакетом:

- **Установить**: скачать проверенный официальный бинарник и зарегистрировать systemd-службу без запуска.
- **Обновить**: скачать новую версию с проверкой SHA-256, сохранить настройки DNS и перезапустить службу, если она включена.
- **Удалить**: отключить OxiDNS в sing-box, остановить службу, удалить файлы и настройки. После удаления экран sing-box → DNS скрывает форму конфигурации и показывает место установки.
- **Общее обновление**: обновлять только ранее установленные компоненты; отсутствие OxiDNS не приводит к его автоматической установке.

Релизы скачиваются из svenshi/oxidns через GitHub Releases. При неудаче обновления старый бинарник восстанавливается.

## Поддерживаемые системы и ограничения

Автоматическая установка рассчитана на **Linux x86_64 и ARM64 с systemd**, при запуске панели от root. Для Docker и остальных систем нужен отдельный менеджер контейнеров/служб.

При отключении OxiDNS его сохранённая конфигурация не удаляется; при удалении пакета служебная конфигурация удаляется. Управление и статус доступны только через авторизованный API 3x-ui; самостоятельный WebUI OxiDNS на открытом порту не запускается.

Публичный DoH является резолвером. Не открывайте сервис публично без понимания возможных злоупотреблений и сетевых ограничений. Для крупных развертываний дополнительно необходимы ограничения нагрузки и мониторинг. OxiDNS не заменяет авторитативный DNS-хостинг доменной зоны.

## API

Настройки DNS и кнопки обновлений обращаются к авторизованным маршрутам 3x-ui:

- GET /panel/api/oxidns/status (с ?check=true проверяет последний официальный релиз);
- GET /panel/api/oxidns/logs (последние 80 записей журнала выделенной systemd-службы);
- POST /panel/api/oxidns/setup и /disable (setup требует предварительной установки компонента);
- POST /panel/api/oxidns/validate (проверка выбранной конфигурации, включая DNS-имя и сертификат, без применения);
- POST /panel/api/oxidns/install, /update и /remove.

Код управления службой находится в internal/oxidns/; интеграция sing-box — в internal/web/service/singbox.go. Поля управления OxiDNS не сохраняются в пользовательском JSON sing-box.

## Google и Яндекс DNS

Google Public DNS подключается по DoT (dns.google:853, bootstrap 8.8.8.8).
Яндекс DNS использует официальные режимы с шифрованием DoT:

- **Базовый:** common.dot.dns.yandex.net:853, bootstrap 77.88.8.8;
- **Безопасный:** safe.dot.dns.yandex.net:853, bootstrap 77.88.8.88;
- **Семейный:** family.dot.dns.yandex.net:853, bootstrap 77.88.8.7.

Выбранный режим применяется после нажатия «Сохранить и применить», остальная конфигурация sing-box сохраняется. Уровень фильтрации определяется самими DNS-провайдерами, а не программой 3x-ui.

Источники: https://dns.yandex.ru/ и https://developers.google.com/speed/public-dns/docs/dns-over-tls

## Проверка работы DNS

На странице sing-box → DNS нажмите «Проверить DNS-запрос». Панель выполнит настоящий запрос имени example.com через локальный DNS и проверит наличие IP-адреса, а не только запущенный процесс. При недоступности зашифрованного DNS-провайдера (например, блокировке TCP-порта 853) панель покажет объяснение и предложит проверить сеть либо выбрать другого провайдера. Во время включения службы такая проверка также выполняется автоматически: при неудаче конфигурация откатывается.

## Восстановление после ошибки

Если запуск OxiDNS завершился ошибкой, панель восстанавливает предыдущее состояние службы. Когда DNS был выключен, наличие ранее созданного config.yaml не приводит к повторному запуску службы. Откат системных операций выполняется в отдельном ограниченном по времени контексте и сообщает об ошибках восстановления.

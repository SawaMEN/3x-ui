# Vision и REALITY в модифицированном Sing-box

Продолжение в panel6: [mKCP, XHTTP и балансировщики](sing-box-transport-balancer-support.md).

Поддержка закреплена в сборке `sawamen-b5749002266b-panel5` ветки `update`.
Исходные ревизии ядра сохранены; изменения применяются воспроизводимыми
патчами из `deploy/hiddify` при сборке. Общий кеш Go-модулей не изменяется.

| Параметр панели                                        | Реализация                                                                            |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| VLESS inbound `testseed`                               | Настройки padding серверного Vision writer                                            |
| VLESS outbound `testseed`                              | Настройки padding клиентского Vision writer                                           |
| VLESS outbound `testpre`                               | Пул предварительных транспортных/TLS-соединений до отправки VLESS-запроса             |
| REALITY `mldsa65Seed`                                  | Дополнительная подпись ML-DSA-65 сертификата, привязанная к ClientHello и ServerHello |
| REALITY `mldsa65Verify`                                | Проверка этой подписи; неверный ключ и отсутствие подписи отклоняются                 |
| REALITY `minClientVer`, `maxClientVer`                 | Проверка версии в REALITY ClientHello                                                 |
| REALITY `serverNames`                                  | Все разрешённые SNI, без усечения списка до первого имени                             |
| REALITY `xver`                                         | PROXY protocol 0/1/2 к handshake target                                               |
| REALITY `limitFallbackUpload`, `limitFallbackDownload` | Настоящие лимиты fallback в TLS-библиотеке                                            |

`testseed` содержит четыре целых числа. Проверка исключает отрицательный padding,
нулевые диапазоны генератора и переполнение 16-битных длин кадра. При отсутствии
параметра сохраняется стандартный набор `[900, 500, 900, 256]`.
`testpre` ограничен 64 соединениями и требует Vision без multiplex. Пул запускается
при первом запросе, обновляет соединения после двух минут и закрывает их при
остановке outbound. Ошибки соединения используют задержку, а не бесконечный tight loop.

REALITY использует 32-байтовый seed ML-DSA-65 и 1952-байтовый ключ проверки в
base64url без padding. Seed должен отличаться от приватного ключа X25519.
Подпись соответствует расширению сертификата Xray; обычный REALITY остаётся
совместимым. Клиент с заданным ключом ML-DSA не принимает один только HMAC.
Генерация ключей и редактирование параметров возвращены в формы панели.
Ошибочный или неполный импортированный `testseed` сохраняется до проверки,
а не исчезает при преобразовании формы в JSON.

## Проверка

- Реальные локальные REALITY handshake и передача данных: Sing-box → Sing-box,
  Xray → Sing-box и Sing-box → Xray.
- Отказ при неверном ML-DSA ключе и при отсутствии обязательной подписи;
  обычный REALITY без ML-DSA.
- Реальная передача данных через TLS + VLESS Vision с разными `testseed` на
  клиенте и сервере и включённым пулом предварительных соединений.
- Исправлена арифметика указателей на внутренние буферы TLS в старой Vision-библиотеке (падение checkptr).
- Padding/unpadding, закрытие и сброс пула, закрытие до первого запроса;
  проверка race detector.
- Проверка преобразованных inbound/outbound конфигов настоящей сборкой ядра;
  повторная матрица протоколов и транспортов.
- Применение патчей к чистым закреплённым исходникам; сборки purego и musl.
- 1564 существующих frontend unit/component теста и три новых проверки Vision; typecheck, lint и Vite build. Storybook требует отсутствующий Chromium.

Эти локальные проверки не требуют внешних серверов. Полный запуск панели с
системными сетевыми интерфейсами в текущем окружении ограничен разрешением netlink.

## Оставшиеся несовместимые функции

В panel5 оставались ограничения Reverse, mKCP, XHTTP и балансировщиков.
В panel6 добавлены Reverse, mKCP, режим download и динамические стратегии;
проверки и оставшиеся ограничения описаны в [отчёте](sing-box-transport-balancer-support.md).
Вложенные XHTTP downloadSettings добавлены в panel7; семантика и ограничения
описаны в отчёте.

Для использования новых параметров требуется ядро **panel5**: старый бинарник
panel4 не содержит этих изменений. Сборка: `tools/build-hiddify-core.sh`;
release/Docker используют тот же комплект патчей с профилем musl.

# DNSTT в 3x-ui — отдельный зашифрованный DNS-туннель

DNSTT **не заменяет DNS-резолвер OxiDNS** и не является самостоятельно работающим
SOCKS5/VPN-протоколом. Он доставляет двунаправленный TCP-поток от клиента через
DNS-запросы к локальному TCP-сервису на вашем сервере.

## Быстрый запуск

1. Откройте **Настройки → Обновления пакетов и ядер Linux → DNSTT** и установите
   бинарник. Или перейдите в **sing-box → DNS → DNS-туннель — DNSTT** и нажмите
   **Установить DNSTT**.
2. Введите отдельный домен, например `t.example.com`, публичный IPv4 VPS и
   локальный TCP-порт, куда следует направлять трафик (по умолчанию SSH: 22).
3. Добавьте DNS-записи в родительской зоне `example.com`:

   ```dns
   ns.example.com. IN A 203.0.113.2
   t.example.com. IN NS ns.example.com.
   ```

   Не ставьте `ns.example.com` под делегированный `t.example.com`.
   DNS-провайдер должен позволять установить произвольную NS-запись для
   поддомена. На VPS разрешите входящий UDP/53. Панель не управляет регистратором
   DNS или внешним firewall.

4. Нажмите **Создать и включить DNSTT**. Система автоматически создаст
   долговременную пару ключей Noise, зарегистрирует systemd-службу и запустит
   сервер. Приватный ключ хранится в `/etc/x-ui/dnstt/server.key` (0600);
   API показывает **только публичный ключ**.
5. Нажмите **Проверить NS-делегирование домена**. Панель запросит публичные DNS-записи зоны, проверит NS-сервер и его IPv4. Это диагностика делегирования, а не гарантия прохождения UDP/53 или доступности DNSTT через каждого оператора.
6. Скачайте `dnstt-client` под свою платформу и используйте команду из панели:

   ```bash
   # Клиент через рекурсивный DoH
   dnstt-client -doh https://cloudflare-dns.com/dns-query -pubkey PUBLIC_KEY t.example.com 127.0.0.1:7000

   # Клиент через рекурсивный DoT
   dnstt-client -dot 1.1.1.1:853 -pubkey PUBLIC_KEY t.example.com 127.0.0.1:7000

   # Клиент через обычный рекурсивный DNS, UDP/53
   dnstt-client -udp 1.1.1.1:53 -pubkey PUBLIC_KEY t.example.com 127.0.0.1:7000
   ```

   Подключайте SSH-клиент к `127.0.0.1:7000` с учётными данными от сервера
   (`ssh -p 7000 user@127.0.0.1`), если цель — порт 22.

## Что поддерживается

- Управляемый `dnstt-server` на Linux amd64 и arm64, systemd, статус, установка,
  обновление и полное удаление, автоматическая генерация неизменяемых ключей.
- Выделенная DNS-зона, NS/A-подсказки, произвольный UDP-порт входа и локальный
  TCP-порт назначения.
- Клиентские режимы **UDP DNS, DoH и DoT**. DNS-запросы проходят через
  рекурсивный резолвер клиента. Поддержка HTTP/3 определяется выбранным DoH
  резолвером и клиентской реализацией; **DNSTT не следует смешивать с сервером
  DoH/H3, DoQ или DoT в OxiDNS**.
- Состояние и кнопки доступны независимо от конфигурации sing-box и OxiDNS.
- Ключи при отключении сохраняются, при удалении стираются; после удаления
  настройки DNSTT больше не отображаются как установленный компонент.

## Безопасность

**Публичный ключ DNSTT аутентифицирует сервер перед клиентом, но не авторизует
подключающихся к туннелю.** Указанный локальный сервис обязательно должен иметь
собственную аутентификацию. По умолчанию указан SSH, а не открытый HTTP/SOCKS
прокси. Параметр назначения всегда ограничен интерфейсом `127.0.0.1`; произвольные
внешние TCP-адреса не принимаются. Не перенаправляйте DNSTT на незащищённый
локальный прокси.

## Сборка и происхождение бинарников

Исходный DNSTT разработан David Fifield:
https://www.bamsoftware.com/software/dnstt/ .

Для установки используется опубликованная **сторонняя сборка зеркала**
https://github.com/NNdroid/dnstt/releases/tag/2026-05-01-0c5c52a
(не официальный выпуск автора). Версия и два SHA-256 для Linux amd64/arm64
зашиты в установщик, а скачанный файл проверяется до запуска. В CI также
проверяются SHA-256 server/client amd64 и передача настоящего TCP-потока.
Перепроверяйте доверие к сторонним сборкам в вашей инфраструктуре.

Для Linux можно скачать соответствующий клиент со страницы релиза. Ключ
`server.key` клиенту **никогда не передавать**.

## Ограничения автоматизации

Без доступа к вашему DNS-регистратору невозможно автоматически создать
публичную NS-делегацию. Панель выдаёт готовые записи, но их необходимо
добавить у DNS-провайдера. Также надо открыть UDP/53 в firewall.
DNSTT способен работать поверх некоторых ограниченных DNS-сетей, однако
результат зависит от поведения рекурсивного резолвера и доступности NS-записей;
успех локального теста не гарантирует работу через любого оператора.

# Anti-DPI

Вкладка «Дополнительные настройки → Anti-DPI». Изменения сети по умолчанию отсутствуют.

## Первая версия

- Проверка DNS, TCP и TLS из сети сервера для собственного публичного домена на 443.
- Локальный импорт JSON [Siberian Check](https://github.com/iddserg/siberian-check).
- Разделение асимметрии и неопределённого результата: одновременный таймаут не является доказательством фильтрации.
- Повторное использование существующих опциональных балансировщиков подписок и Observatory, без дублирования модели данных.

## Исследования

Siberian Check использует контрольные TLS-проверки, сравнивает ошибки и различает отпечатки.
[dpi-ch](https://github.com/hyperion-cs/dpi-checkers) покрывает дополнительные классы сетевых ограничений.
[MEKO](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO) исследует серверные TCP-механизмы, включая правила ограничения соединений и интеграцию zapret2. Настройки MTProto не следует автоматически переносить на все VPN: общий IP абонентов CGNAT и разные транспорты могут давать ложные срабатывания.
В 3x-ui уже есть zapret2 для исходящего трафика; это не эквивалент защиты входящих соединений.

## Следующие этапы

1. Сбор измерений со стороны клиента без VPN, ограничение частоты активных тестов.
2. Сопоставление результатов с серверными метриками, состоянием портов и сертификатов.
3. Расширенные диагностические проверки DPI-CH, отдельная оценка IPv4/IPv6.
4. Аудит совместимости опциональных мер на тестовом сервере, отдельное применение и откат; не менять глобальный firewall автоматически.
5. Проверка на мобильных операторах и в условиях CGNAT; резервирование независимых точек входа.

Серверная проверка не устанавливает наличие блокировки у абонента. Импорт отчёта не изменяет настройки и не отправляет данные внешним сервисам.

## Adaptive Connect

Добавлены аудит групп подписок (доступные участники, стратегия, узлы, транспорты) и независимый пакет `internal/adaptiveconnect` для будущего подключения к Hiddify Core. Аудит не утверждает, что разные узлы имеют независимые публичные IP.

Алгоритм разделяет наблюдение и фактическое переключение: решение не меняет активный туннель до подтверждения успешной активации вызывающим кодом. Поддерживаются последовательные ошибки, подтверждение восстановления, срок годности наблюдений, пауза между переключениями, опциональный возврат к предпочтительному соединению. Непроверенный резерв не выбирается; автоматический выход без VPN отсутствует.

Пакет пока не подключён к рабочему ядру: для этого требуются измерения реальной передачи данных со стороны клиента, управление туннелем и изоляция истории по сети. Существующие балансировщики Xray продолжают работать без изменения формата подписки. Нативная подписка Hiddify (GetHiddifySingBoxJson/buildHiddifySingBoxSubscription) передаёт отдельные outbounds/endpoints, не группы Xray.

## Целевая платформа: Hiddify

VetrOFF Client исключён из плана; основной клиент — [Hiddify](https://github.com/SawaMEN/hiddify-app), ядро Hiddify Core. Не добавлять зависимость от VetrOFF Client или отдельный формат подписки без необходимости. Следующий этап — проверить импорт групп и URLTest в реально используемом Hiddify Core, затем интегрировать алгоритм выбора с проверкой передачи данных и подтверждением переключения. Android и macOS должны использовать одинаковые правила состояния. Тестировать подписку с ShadowTLS, WireGuard/AWG и MASQUE, не добавлять скрытые транспорты как отдельные кандидаты. Сохранять ручной выбор, не переключаться на direct.

## Активная проверка Siberian

Добавлена адаптированная проверка с uTLS (Chrome, Firefox, Safari, Android). Требует двух разных имён с действительными сертификатами и одним общим публичным IP. Сначала проверяются оба имени, затем четыре параллельных TLS-соединения и одно контрольное. Ошибки TCP, сертификатов, контрольного соединения и неполная проверка не подтверждают фильтрацию. Не используются случайные SNI и отключение проверки сертификата. Ограничение — одна активная проверка в минуту, один общий диагностический запрос, общий таймаут. Выполняется исключительно по подтверждению администратора; проверка в проблемной мобильной сети пока выполняется внешним Siberian Check. Это не точное воспроизведение upstream и не доказательство блокировки.

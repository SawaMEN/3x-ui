# Reverse, транспорты и балансировщики: panel8

Изменения доступны в ветке `update`; требуется сборка
`sawamen-b5749002266b-panel8`. Патчи применяются к закреплённым исходникам Sing-box
и его зависимостей. Отдельный процесс Xray не запускается.

| Возможность           | Результат                                                                                                            |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| VLESS Reverse         | Авторизованный command 4, обратный mux, маршрутизация TCP/UDP, переподключение и учёт трафика                        |
| mKCP                  | Транспорт подключён к VLESS, VMess и Trojan для inbound/outbound и native JSON                                       |
| mKCP + TLS            | Реальная передача данных через TLS поверх mKCP проверена                                                             |
| Legacy seed/header    | Используются оригинальные механизмы mKCP Xray: seed, SRTP, uTP, WeChat, DTLS, WireGuard и отсутствие маски заголовка |
| mKCP параметры        | MTU, TTI, uplink/downlink capacity, cwndMultiplier, maxSendingWindow передаются в транспорт                          |
| XHTTP download mode   | Импортируется и проверяется отдельно; download передаётся как stream-down, как в Xray                                |
| XHTTP padding         | Исправлена проверка собственных ключей и размещения padding в header/cookie/query/queryInHeader, включая tokenish    |
| Random / roundRobin   | Динамический выбор при каждом соединении, а не один постоянный узел                                                  |
| LeastPing / leastLoad | Применяются алгоритмы закреплённой версии Xray к результатам проверок через исходящие Sing-box                       |
| Fallback              | Выбирается при отсутствии пригодных кандидатов; может находиться вне основного списка                                |
| Observatory           | subjectSelector, probeURL, probeInterval и enableConcurrency связаны с проверками ядра                               |
| Burst observatory     | sampling, timeout, HTTP HEAD/GET, статистика RTT, failure rate и connectivity используются при проверках             |

Reverse возвращён в формы клиентов и исходящих VLESS. На принимающей стороне
`clients[].reverse.tag` создаёт исходящий `vless-reverse` с этим тегом; на стороне
моста `users[].reverse.tag` становится тегом входящих для правил маршрутизации.
Обратный исходящий устанавливает канал после запуска ядра и переподключается
после обрыва. Он не может быть обычным исходящим или маршрутом по умолчанию.
Sniffing моста преобразуется в действия маршрутизации, включая изменение адреса.
Авторизация проверяет UUID, flow и разрешение Reverse; обычные и обратные команды
для каждого аккаунта разделены. Счётчики пользователя учитывают физический канал
один раз, включая служебные данные mux; он регистрируется также в Clash connections.
На стороне моста физический исходящий канал учитывается по его outbound tag с
правильными направлениями uplink/downlink. Отключённая статистика не создаёт пустой tracker.
UDP сохраняет адрес каждого пакета и поддерживает datagrams длиной 0–8192 байта —
предел закреплённого mux. Более крупный пакет отклоняется до записи.

mKCP возвращён в формы VLESS/VMess/Trojan. Capacity ограничена значениями,
для которых вычисления библиотеки не переполняются. Окно отправки должно быть не
меньше MTU. Legacy seed/header нельзя одновременно смешивать с явными UDP masks;
при использовании finalmask он переносится на транспорт для одинаковой обработки
на обеих сторонах, без повторного применения.

Динамические группы используют observatory/burstObservatory из настроек панели.
Для стратегий с health-check и fallback требуется явно заданный URL и подходящие
subjectSelector. Проверки выполняются через соответствующий outbound.
Connectivity проверяет прямое подключение после ошибки burst probe, чтобы
общая потеря сети не учитывалась как неисправность отдельного узла.

Исправлены дополнительные ошибки, обнаруженные при проверке:

- Гонки общего состояния Vision при одновременном чтении и записи.
- Падение Vision при разделении UUID/заголовка padding между TCP чтениями и
  некорректной длине session ID в ServerHello.
- Гонки публикации сессии и адреса UDP в mux, потеря пустых UDP datagrams.
- Гонки освобождения буферов, завершения и изменения deadline в mKCP.
- Конкурентное изменение SRTP/DTLS заголовков при работе нескольких UDP сессий.
- Гонки публикации reader, чтения/закрытия очереди и передачи владения буферами XHTTP.
- Зависание генератора padding с алфавитами длины, делящей 256.
- Изменение алгоритма round-robin при простом чтении статуса группы.
- Изменение объекта history одновременно с чтением его API: хранятся снимки.

## Проверка

- Reverse: реальная передача TCP и UDP через VLESS и оригинальный mux Xray;
  native bridge через TLS и Vision, переподключение и завершение; отказ обычным
  и неизвестным UUID, flow mismatch, отсутствующий portal; счётчики пользователя.
- Заголовок command 4 сравнивается с кодеком закреплённого Xray для обычного flow
  и Vision. Проверены пустые и 8192-byte UDP packets, смена назначения и deadlines.
- mKCP: реальные соединения Sing-box ↔ Sing-box и Xray client → Sing-box server,
  шесть вариантов маски, с seed и без него; TLS и передача данных.
- XHTTP: четыре download mode, восемь сочетаний размещения/method padding,
  передача данных и полный существующий набор тестов транспорта.
- Балансировщики: четыре алгоритма, выбор исправного узла, реальные HTTP probes
  через dialer исходящего, fallback и закрытие до запуска.
- Все новые проверки ядра проходят race detector.
- Повторная проверка native JSON и матрицы VLESS/VMess/Trojan × транспорты × inbound/outbound
  настоящей сборкой ядра, включая mKCP.
- Frontend: ранее полный набор unit/component (1567 успешных проверок), после
  добавления Reverse — 58 проверок форм/адаптера/возможностей; typecheck, lint и build.
- Полная сборка ядра purego с закреплёнными 12 build tags. Новые патчи повторно
  применены к чистым исходникам, результат совпадает с проверенным исходным кодом.
  Профиль musl для новых расширений в этом окружении повторно не собирался.

## Ещё не реализовано

В panel7 вложенные XHTTP downloadSettings поддерживаются как последовательные
переопределения: самый глубокий блок определяет endpoint скачивания. Это не цепь
прокси. Каждый уровень проверяется; максимум — 8 блоков. Отдельный download
несовместим с верхним stream-one. Параметры leaf (TLS, detour, path, headers, xmux)
применяются к реальному GET каналу; промежуточные endpoints не вызываются.
Проверка Reverse охватывает TCP transport, TLS и Vision; реальные соединения
Reverse через остальные транспорты отдельно не проверялись. Системные интерфейсы
и полный запуск маршрутизатора остаются ограничены разрешениями netlink текущего
окружения. Поддержка в этом отчёте не означает проверку на внешних VPS.

В panel8 сборка переведена на Go 1.27.2 и golang.org/x/net v0.60.0 с исправлениями HTTP/2, TLS и стандартной библиотеки. Протокольные настройки panel7 сохранены.

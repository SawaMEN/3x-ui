# Быстрые маршруты: исправления 13 ноября 2026

Исходное состояние main: `134eecda39758b4d399dc54ae4691085b4ef94f9`.
Сценарий: клиент подключается к российскому входящему, российское ядро
использует зарубежное входящее как управляемое исходящее `node-route-N`.
Доступа к рабочим серверам и их журналам в этом запросе нет; точная причина
конкретного пользовательского таймаута не установлена.

## Проверенный путь

Прочитаны компилятор/редактор быстрых правил, получение локальных источников,
API targets/ensure/probe, создание служебного клиента, синхронизация и запуск
ядра назначения, построение исходящего из ссылки, инъекция в Xray/native
конфигурацию и обработчики сохранения. Проверены связанные тесты и приоритеты
правил. Это проверка подсистемы быстрых маршрутов, не завершение общего аудита
репозитория и не подтверждение всех комбинаций протоколов на реальных нодах.

## Шесть исправлений

1. Список Xray содержит также теги удалённых и выключенных подключений.
   Быстрый редактор раньше сохранял их как локальные источники. Теперь метаданные
   исключают их даже из исходного снимка. Неизвестные сгенерированные relay-теги
   сохраняются. Старые ошибочные быстрые правила получают предупреждение.
2. Явная подготовка маршрута доверяла fingerprint последней отправки.
   Если зарубежную панель восстановили или удалили служебного клиента прямо
   на ней, совпадение тега и старого fingerprint пропускало восстановление
   учётных данных. Теперь ensure повторно отправляет выбранное входящее перед
   активацией. Обычная фоновая delta-синхронизация не менялась.
3. Повторное включение сохранённого маршрута не подготавливало зарубежного
   клиента. Теперь включение ожидает ensure; ошибка оставляет правило выключенным.
4. Доменные/IP/портовые исключения могли добавляться после широкого
   panel-owned правила по входящему. Теперь исключения вставляются перед
   пересекающимся управляемым fallback; повторное сохранение, смена назначения
   и включение ремонтируют старый неверный порядок. Ручные правила сохраняют
   относительный порядок; непересекающиеся fallback не перемещаются.
5. GetScopedInboundLinks читал глобальный provider без блокировки и мог
   столкнуться с регистрацией provider. Используется единый защищённый снимок.
6. Индикатор загрузки зарубежных целей никогда не включался. Теперь загрузка
   обозначается, старый список сбрасывается при смене движка, создание ждёт
   получения источников и целей.

## Применение

Обновить российскую управляющую панель до коммита с этими исправлениями.
Если российский входящий находится на отдельной удалённой ноде, правило должно
применяться именно на сервере, принимающем клиентское соединение; центральное
локальное правило само по себе не меняет маршрутизацию отдельной ноды.

В быстром маршруте заново выбрать локальное российское входящее и зарубежную
цель. Смена назначения или выключение/включение запускает восстановление
служебного клиента. После этого выполнить общее сохранение настроек.
Маршрут: клиент -> РФ -> зарубежная нода -> Интернет.

Остаётся проверить этот путь на рабочих/испытательных нодах с доступным netlink,
а при таймауте сопоставить журнал российского ядра и результат проверки ноды
после сохранения. Изменения в репозитории не обновляют рабочие серверы автоматически.

## Продолжение: настоящая передача трафика Xray

Добавлен `internal/sub/node_route_xray_live_test.go`. Тест самостоятельно запускает
три отдельных процесса с версией Xray, закреплённой в go.mod: клиент, российское
ядро и зарубежное ядро. Используются настоящие ссылки из LinkProvider, нормализованные
записи клиентов и полный CoreService.GetXrayConfig, включая resolver/injector
управляемого исходящего. Доступ к внешним серверам не нужен, весь трафик — loopback.

Матрица содержит 10 сценариев:

| Зарубежное подключение / условие | Контроль |
|---|---|
| VLESS TCP | HTTP и остановка зарубежного процесса |
| VMess TCP | HTTP и остановка зарубежного процесса |
| VLESS WebSocket | HTTP и остановка зарубежного процесса |
| VLESS TLS | Настоящий TLS с SHA-256 pin, HTTP и остановка |
| Trojan TLS | Настоящий TLS с SHA-256 pin, HTTP и остановка |
| Shadowsocks | HTTP и остановка зарубежного процесса |
| VLESS Reality, существующий служебный клиент | Два вызова ensure, неизменность UUID, HTTP и остановка |
| VLESS Reality, новый служебный клиент | Создание через ensure, повторный ensure, неизменность UUID, HTTP и остановка |
| VLESS Reality Vision | HTTP и остановка зарубежного процесса |
| Отключённый служебный клиент | Ядро запускается с блокирующим исходящим; HTTP-сервер не получает запрос |

В каждом положительном сценарии исходящий по умолчанию на российском ядре —
blackhole. После остановки зарубежного процесса новый HTTP-запрос обязан завершиться
ошибкой и не увеличивать счётчик запросов конечного HTTP-сервера. В сценариях ensure
эмулируется только HTTP API удалённой панели; работа с центральной БД, создание
клиента, отправка полного входящего, построение ссылки и весь путь передачи
трафика используют код проекта и настоящие ядра.

Для loopback-стенда явно разрешён только 127.0.0.1/32 в finalRules зарубежного
freedom: закреплённый Xray по умолчанию блокирует private-адреса за VPN-входящими.
Рабочие настройки безопасности панелей и серверов не менялись.

Первоначальная попытка запустить три Instance в одном процессе оказалась
нестабильной на Reality. Выбор отдельных процессов соответствует реальному
размещению нод и разделяет глобальные registries/loggers/transport state.
Гипотеза об обязательном Vision не подтвердилась: прежний код без изменения
flow прошёл два повторных изолированных прогона. Экспериментальная правка flow
отменена; дополнительного изменения настроек пользователей нет.

В прежнем native-core live-тесте исправлен неограниченный SOCKS handshake:
единый deadline теперь действует с начала соединения, включая SOCKS negotiation.
Сам native-core тест остаётся обязательным при заданном HIDDIFY_CONFIG_CHECK_BINARY;
ограничение netlink этой среды не скрывается и не считается успешным прогоном.

Запуск автономной Xray-проверки:

```sh
go test ./internal/sub -run '^TestNodeRouteXrayLiveSubscriptionCascade$' -count=1 -v -timeout 2m
```

Финальный объединённый прогон: **10/10 сценариев PASS**, вместе с тестами реальных
ссылок, TLS-параметров и flow. Целевые service/runtime/singbox-тесты — PASS;
go vet sub/service — PASS. Прогон с `-race` для нового служебного клиента Reality
и отключённого служебного клиента — PASS. Дополнительные повторы изолированных
Reality-сценариев подтверждают стабильность; зависимостей go.mod/go.sum не добавлено.

Передача TCP/HTTP в испытательной Xray-цепочке проверяется независимо от ограничения
native-core. UDP, sidecar-протоколы и рабочие ноды этим тестом не подтверждаются.
Для закрытия конкретного таймаута остаются нужны выбранное ядро, протоколы обоих
входящих и журнал российского ядра за неудачную попытку после применения исправлений.

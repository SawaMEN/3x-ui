# Проверка протоколов, транспортов, JSON и функций панели

Этот отчёт относится к сборке panel4. Поддержка Vision testseed/testpre и REALITY ML-DSA, добавленная в panel5, описана в [новом отчёте](sing-box-protection-support.md).

Дата: 2026-10-12. Ветка: `update`. Ядро: модифицированный Sing-box,
закреплённая ревизия `b5749002266b9782803669138494ef6937eb4e95` с патчами
из `deploy/hiddify`. Изменения ядра хранятся как проверяемые overlays в этой
ветке; отдельный репозиторий ядра не публиковался.

## Результат и подсчёт

Исправлены **24 подтверждённые группы дефектов**. Требование найти именно
200 независимых ошибок не подтверждено результатами проверки. Для одного
класса ошибок числовых параметров добавлены **208 негативных сценариев**,
которые не выдаются за 208 самостоятельных багов.

Проверка сочетает анализ путей UI/API/генератора/процесса, тесты компонентов,
сервисов, зависимостей и реальный `check -c` двух сборок ядра. Она не доказывает
корректность каждой функции при любых входных данных и не заменяет передачу
трафика между реальными клиентом и сервером.

## Исправленные дефекты

| № | Причина / проявление | Исправление и подтверждение |
|---|---|---|
| 1 | Массовый импорт native `{type, tag, ...}` обходил преобразование в формат панели | Общий нормализатор для одного объекта, массива и `{outbounds: [...]}`; тесты native JSON |
| 2 | Неправильные строки импорта могли попасть в список до обнаружения ошибки в следующей строке | Вся партия проверяется до изменения списка; malformed-import tests |
| 3 | Импорт создавал конфликтующие или некорректные теги | Проверка типов/пробелов/дубликатов, генерация свободных имён; frontend/backend tests |
| 4 | Backend ожидал `protocol` и не принимал native JSON с `type` | `NormalizeOutboundInput` на входе адаптеров и проверки шаблона; native dialect tests |
| 5 | Необъектные `settings`, `streamSettings`, `mux`, `proxySettings` могли терять смысл при чтении | Отказ с конкретным именем поля вместо преобразования в пустой объект |
| 6 | Числа округлялись/усекались или переполнялись при переводе портов и настроек | Проверка целых значений и границ до преобразования; 208 негативных сценариев |
| 7 | Валидатор принимал регистр `type/transport.type`, но в ядро уходило исходное написание | Канонические значения в runtime-копии; исходный JSON не мутируется |
| 8 | Валидация исходящих сохраняла ограничения stock-профиля для XHTTP/RAW | Удалён переключатель stock/modified; native XHTTP и RAW проверены бинарником |
| 9 | Общий редактор JSON сохранял данные после проверки отдельных outbound, без полного core preflight | `SaveValidatedXraySetting` строит полный кандидат из снимка БД и вызывает ядро до сохранения; API использует этот путь и контекст запроса |
| 10 | Ошибки восстановления native-шаблона/конфига скрывались при неуспешном применении | Возвращаются вместе с исходной ошибкой через `errors.Join` |
| 11 | UI предлагал multiplex для HTTP/SOCKS, не поддерживающих эту опцию | Список допустимых протоколов согласован с адаптером |
| 12 | Новые inbound/outbound можно было настроить на отсутствующий mKCP | Удалены пункты выбора, обе формы и недостижимая инициализация KCP |
| 13 | Новый loopback outbound предлагался при отсутствии поддержки в Sing-box | Удалены пункт выбора, форма и её неиспользуемые переводы |
| 14 | Naive outbound собирался без необходимой Cronet-зависимости; glibc-библиотека не подходит Alpine | Профили purego с закреплённой библиотекой и static musl с LLD; релиз/Docker используют musl; Naive включён в smoke check |
| 15 | HTTP/1-вариант MASQUE/HTTP client сериализовался как `nil` и ломал объединение JSON-объектов | Патч `http1-options.patch`, round-trip тесты клиента/сервера и HTTP client |
| 16 | Изолированная проверка outbound использовала общий адаптер и теряла расширения модифицированного ядра | Используется тот же адаптер `hiddify.TranslateOutbound`, что и рабочий процесс; XHTTP probe contract test |
| 17 | Проверочный конфиг терял default DNS resolver для серверов с доменным именем | Resolver сохраняется в `route`; проверка конфига реальным ядром |
| 18 | Mieru отсутствовал в native-списке общего редактора и попадал в обычную TCP-проверку | Добавлены шаблон и выбор протокола, проверка через ядро на frontend/backend; native Mieru matrix case |
| 19 | Ответ IP-сервиса принимался как адрес без проверки и без ограничения размера | Проверка IP/публичного unicast-адреса, лимит тела; локальные HTTP tests |
| 20 | IPv6 lookup мог сохранить IPv4 и прекратить поиск | Проверяется семейство адреса, неправильный ответ не останавливает fallback |
| 21 | Возможности панели ошибочно отрицали работу GeoIP/GeoSite через преобразование геоданных | Исправлен capability response Sing-box; API/model tests |
| 22 | Форма/адаптер автоматически добавляли Vision `testseed`, который ядро не поддерживает | Удалены новые seed/testpre controls и автоматическое заполнение; обычный Vision остаётся доступен; adapter regression test |
| 23 | Форма REALITY предлагала создавать ML-DSA-настройки, не имеющие соответствия в этом ядре | Новая конфигурация их не создаёт; существующие значения показаны read-only с предупреждением и явной очисткой |
| 24 | Формы клиентов и исходящих предлагали неподдерживаемый VLESS Reverse | Новое значение не предлагается; сохранённое доступно для просмотра и явного удаления; исходные wire-поля сохранены |

Ранее предполагаемый дефект «native-шаблон не проверяется при остановленном
ядре» **не включён** в этот список: `WriteConfig` уже проверял временный
кандидат. Добавленная повторная проверка удалена. Регрессионный тест защищает
проверку и восстановление при остановленном процессе.

Внутренняя синхронизация маршрутов при изменении inbound использует прежний
путь хранения: его нельзя заменять preflight по ещё не завершённой транзакции
inbound. Полная проверка применяется к пользовательскому JSON-редактору.

Проверены **purego + libcronet** и **статическая musl-сборка** на Linux/amd64.
Статическая сборка имеет закреплённую ревизию и нужные теги, не содержит
ELF interpreter и принимает Naive без отдельной `.so`. Для корректной линковки
Cronet нужен LLVM LLD; он добавлен в release workflow и Docker builder.
Arm64 и полный Docker build должны дополнительно пройти CI.

## Удалённый код и тесты

Удалены:

- Формы KCP inbound/outbound, их exports и недостижимая инициализация.
- Форма создания loopback outbound и её неиспользуемые переводы.
- Неподдерживаемые новые Vision seed controls и генерация REALITY ML-DSA в UI.
- Неиспользуемые `shouldSkipLegacyUnencryptedOutboundRejection`,
  `compareXrayCoreVersions`, `parseXrayCoreVersionParts` и их тесты.
- Stock-version gates `supportsMinor`, связанные тесты NativeAPI/MASQUE по
  произвольной версии. Возможности определяет закреплённый профиль.
- Переключатель `Config.Hiddify` и обход валидации через подмену XHTTP на HTTP.
- Snapshot удалённой KCP-формы; другие snapshots согласованы с новым UI.

Сохранены используемые форматы БД, wire JSON, ссылки/подписки, миграционные
aliases, legacy readers и тесты rollback/маршрутов/импорта. Массовое удаление
compatibility-кода нарушило бы существующие данные. Реальные runtime-тесты
не удалены: команда исправлена на `srun`, ограничения среды видны как skip.

## Проверки и ограничения

- Матрицы конфигураций и full DB config прошли проверку статическим ядром.
- Изменённые пакеты Go и core-migration tests проверены; outbound-probe tests
  проходят с проверкой реальным ядром.
- Race для core/адаптеров/probe проходит; для изменённых сервисных путей
  выполнен отдельный race-прогон. Общий race service превысил 240 секунд во
  время bcrypt-инициализации очередной БД, не показав race-report.
- Frontend: 151 test file, 1564 passed / 1 skipped; typecheck, lint и production build проходят.
  После последних изменений форм повторно выполнен полный unit/component
  suite; отдельный ранний timeout двух Vision tests устранён повторным
  прогоном с 15s deadline (без изменения production-кода ради теста).
- Shell preflight/migration suite: 15 сценариев, синтаксис build/install scripts.
- Проверка закреплённого исходного дерева выполнялась до overlays; патчи
  проверены отдельно. `go vet` не запускает сетевые функции приложения.
- Полный `go test ./...` **не объявляется успешно пройденным**: автоматическая
  проверка дважды отклонила его из-за оставшегося вызова `api4.ipify.org` в
  других тестовых пакетах и передачи публичного IP среды. После отклонения
  общий запуск не повторялся; изменённые сервисы проверены с локальным
  `publicIPTestTransport`, который не обращается к внешним провайдерам.
- Storybook/browser tests, PostgreSQL и реальные remote handshakes не входят
  в подтверждённый результат. `check -c` не заменяет передачу TCP/UDP трафика.

Для окончательной проверки подключения нужны реальные клиент/сервер,
сертификаты и совпадающая аутентификация, открытые TCP/UDP порты, доступ к
TUN/netlink/маршрутам и доступные sidecar-бинарники. Эти ограничения не
скрываются числом тестов или формулировкой «все протоколы точно работают».

Your entire configuration — inbounds, clients, settings — lives in the panel's
database. Back it up regularly so you can recover or migrate.

## What to back up

- **The database** — SQLite at `/etc/x-ui/x-ui.db` by default (or your
  PostgreSQL database if you use that backend).
- **Certificates** — anything under `/root/cert/` (or wherever you store TLS
  certs).

## Manual backup

Download a consistent database snapshot from the panel. Do not copy only a running SQLite `.db` file: recent committed data can still be in its WAL file. Stop the panel before making a filesystem copy, or use the panel's snapshot operation.

For complete encrypted recovery, including the token keyring and configured local certificates, use:

```bash
x-ui recovery export --file /root/panel.recovery --password-file /root/recovery-password
x-ui recovery check --file /root/panel.recovery --password-file /root/recovery-password
x-ui recovery restore --file /root/panel.recovery --out /root/panel-restored --password-file /root/recovery-password
```

The password file must be mode 0600 and contain at least 16 bytes. Restore extracts into a new directory for review; it does not replace the running installation. The bundle's `manifest.json` records the original paths. Preserve every key in the node-token keyring, including older rotation keys. A database alone cannot decrypt tokens after moving to a server without that keyring. Recreate external certificate renewal automation separately.

To restore, stop the panel, put the database back in place, and start it again.

<Callout type="warn">
  Restore a backup onto the **same major version** it came from when possible.
  Across major upgrades, let the panel run its migrations rather than forcing an
  old schema.
</Callout>

## Automated bot backups (Telegram)

If you've configured the [Telegram bot](/docs/operations/telegram-bot), enable **`tgBotBackup`** to attach a backup to the periodic report (on the `tgRunTime` schedule, default daily). The bot sends the **database** and **Xray `config.json`** to your admin chat. Admins can also request a backup from the Telegram bot's menu.

## SQLite dump / restore

The `x-ui migrate-db` command converts the SQLite database to and from a plain
SQL text dump (handy for inspection or transferring between machines):

```bash
x-ui migrate-db --dump /root/x-ui.sql       # SQLite -> SQL text
x-ui migrate-db --restore /root/x-ui.sql     # SQL text -> SQLite
```

To move to PostgreSQL instead, see [Database](/docs/reference/database).

<Callout type="info">
  Whatever method you use, store backups **off the server** and test a restore
  occasionally — an untested backup isn't a backup.
</Callout>

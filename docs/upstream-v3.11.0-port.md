# Адаптация MHSanaei/3x-ui v3.11.0

Источник: https://github.com/MHSanaei/3x-ui/releases/tag/v3.11.0.
Upstream: `c621ba9014a6aa21fd7c9ecf45655e44e24ebf13`.
База форка: `f995b5df6bc1140a98c01aadb15f1392e82ef2da`.
Проверены 68 коммитов после v3.10.2. Перенос адаптирован к Hiddify-core,
Telemt и нативной модели клиентов; версия форка сохранена.

## Перенесено

| Область           | Изменения                                                                                                                                                                                                                              |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Безопасность      | Случайные первые учётные данные вместо admin/admin с сохранением порядка инициализации форка; проверка строк WG/AWG-конфигураций; доверенная сторона X-Forwarded-For; журналирование отклонённых CSRF-запросов                         |
| Hosts             | Привязки клиентов, закрытие только соответствующего inbound при удалённом/отключённом Host, пулы SNI, CIDR с ограничением числа адресов, порядок групп и перетаскивание                                                                |
| Нативные подписки | Привязки и hosts-first также для Hiddify/sing-box; отдельные ключи туннелей не подменяются общим клиентом; сохранён старый нативный WireGuard-формат                                                                                   |
| Подписки          | Кэш настроек стандартных proxy-inbound без массива клиентов с инвалидацией после записей; данные WG/AWG и собственных протоколов не обрезаются; no-store; числовой XMUX; opt-in DNS/sniffer удалённого Clash-шаблона                   |
| TLS               | Cipher suites в ссылках и импортерах, соответствующий fingerprint, пресеты, помощник динамического ECH и предупреждение о CDN                                                                                                          |
| Telegram          | Редактируемые экраны, inline-поиск, QR-листы, отдельное состояние администраторов в группах, topics, настройки возможностей бота; статус и конфигурация нативного ядра                                                                 |
| API и узлы        | Индексированный поиск токенов, node-admin для обновления панели, поиск клиентов по subId, порог ошибок для node.down                                                                                                                   |
| Учёт и БД         | Пакетная загрузка идентификаторов, пропуск неизменившихся IP/счётчиков, CAS объединения IP, tombstone после commit, сериализация удаления inbound, восстановление выключенных квотой клиентов без включения заблокированных оператором |
| Мониторинг        | Асинхронное обновление публичных IP с повторными попытками и проверкой IPv4/IPv6; метрики LXC и обозначение недоступных значений; корректный порт частного DoH                                                                         |
| Интерфейс         | Метки и описания полей для screen reader, локаль Ant Design, язык HTML, отмена pointer-перетаскивания правил; сохранены собственные страницы и русские подсказки                                                                       |

Изменение externalProxy обновляет соответствующие импортированные Hosts,
сохраняя правила, которые оператор изменил отдельно. Keepalive принимает
число либо AWG-диапазон; проверка всех присоединённых протоколов выполняется
до первой записи. Пропущенное поле сохраняет ранее заданный явный ноль.

## Архитектурные различия

- XDrive позднее реализован в собственном ядре; см. [нативный перенос](native-xdrive-and-protocol-settings.md).
- Xray v26.10.21, его gRPC pool, Lua/XDNS/finalmask и TUIC→Xray relay
  не заменяют Hiddify-core и его маршрутизацию. Несовместимые формы,
  миграции и управление процессом Xray не включены.
- Kernel AmneziaWG upstream рассчитан на другой runtime. Сохранён собственный
  AWG-путь форка; неработающий переключатель kernel mode не добавлен.
- Docker/release-скрипты собирают собственное ядро форка. Имена Xray/mtg
  не переносятся поверх пакетов Hiddify-core/Telemt.
- Сохранены en-US/ru-RU и собственная навигация, включая DNS, firewall,
  OlcRTC и нативные outbounds. Меню Xray/Sponsors и дополнительные локали
  исходного проекта не возвращаются.
- Исходники и проверенные pins Snell v5/v6 из main сохранены. Перенос панели
  не является новым подтверждением совместимости с Surge или доступности
  протоколов в сетях операторов.

## Проверки

- Компиляция всех Go-пакетов и тестовых пакетов, сборка приложения.
- Наборы Go-тестов и регрессии подписок, Hosts, keepalive, сбросов,
  API scope, tombstone, DoH, публичных IP и Telegram.
- Frontend: typecheck, lint, форматирование, production build,
  unit/component-тесты и повторные проверки исправленных регрессий.
- Отдельная регрессия привязок, отключения Host и порядка групп
  в нативных подписках Hiddify/sing-box.

Локальный Vitest использует thread pool и временный конфиг без Storybook;
сетевые интерфейсы изолированной среды подменены только в тестовом процессе.
Эти настройки не входят в репозиторий. PostgreSQL, браузерный Storybook,
полный race/fuzz и интеграции с внешними бинарниками дополнительно проверяет CI;
локальные прогоны без соответствующих переменных окружения их не подтверждают.

## Дополнительная проверка безопасности

Повторный анализ показал 16 находок, в том числе в неизменённых участках
нативного runtime. Исправлены выбор бинарника из произвольного имени протокола
(теперь четыре разрешённых имени), потенциально переполняющиеся расчёты
ёмкости коллекций и UDP-буфера, начальные двойные слеши/backslash в пути узла
и вывод произвольных ошибок gateway/core-migrate в журнал. Первоначальный пароль также
больше не выводится в журнал; установщик задаёт собственные реквизиты,
при ручной установке их задаёт администратор через `x-ui setting`.

После дополнительной проверки реализованы следующие изменения:

- Получение отпечатка узла выполняется со стандартной проверкой TLS.
  Для самоподписанного или несовпадающего по имени сертификата используется
  публичный сертификат из `tls.CertificateVerificationError`; HTTP-запрос
  недоверенному серверу не отправляется. Перенаправления не выполняются,
  SSRF-защита остаётся включённой.
- FPTN сохраняет закрытый снимок уже проверенной пары сертификат/ключ.
  Изменение исходного файла после проверки больше не подменяет материал
  при копировании в Docker runtime.
- TUIC отслеживает обновление проверенной публичной цепочки сертификатов.
  Приватный ключ и произвольные файлы больше не хэшируются для отпечатка.
  Обновление сертификата по прежнему пути проверяется действительной TLS-парой.
- UDP-буфер расширяется через проверяемый `append` после проверки размера,
  без ручного сложения размера выделяемой памяти.

SHA-256 остаётся в операциях, которым нужны стабильные идентификаторы:

| Место                                                | Назначение                                                                                         |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `externalvpn.FPTNUsername`, `mtproto.nativeUsername` | Стабильное ASCII-имя из публичной метки клиента; это не проверка пароля.                           |
| `tuic.Instance.certificateFingerprint`               | Отпечаток публичной цепочки сертификатов для обновления runtime, без содержимого приватного ключа. |
| Идентификаторы в `outbound_subscription_import.go`   | Дедупликация импортированных конфигураций, а не парольная аутентификация.                          |

Пароль панели хранится как bcrypt. Правила CodeQL и сканирование этих
операций остаются включёнными; автоматическое скрытие предупреждений
не добавлялось. Успех анализа, отсутствие новых находок в PR и состояние
исторических предупреждений GitHub являются разными результатами.

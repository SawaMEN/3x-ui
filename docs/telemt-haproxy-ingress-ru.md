# Общий HTTPS-вход на TCP 443

В настройках Telemt WEB выберите **HAProxy → Общий HTTPS-вход на порту 443**. Режим доступен и в отдельной настройке Telemt WEB, и во входящем MTProto с включённым WEB Proxy.

| Сервис | Пример публичного адреса | Внутренний адрес |
|---|---|---|
| Панель | `https://web.example.com/admin-path/` | `https://127.0.0.1:8443/admin-path/` |
| Подписка | `https://web.example.com/sub-path/<id>` | `http://127.0.0.1:2096/sub-path/<id>` |
| Telegram WEB | `web.example.com:443`, путь `telegram/web` | Локальный порт, выделенный Telemt |
| Заглушка | `https://web.example.com/` | Тот же локальный Telemt |
| NaiveProxy HTTPS | `naive.example.com:443` | TLS на `127.0.0.1:9443` |

- Сначала перенесите панель и подписки на внутренние порты, сохранив доступ к панели через SSH-туннель. У панели должен быть TLS-сертификат, а путь входа должен отличаться от корня.
- Если включены подписки, задайте публичный URL подписок, например `https://web.example.com`. Используйте разные префиксы для панели, подписок и Telemt WEB.
- Для подключения NaiveProxy укажите ID локального TCP-входящего. Его поле SNI должно содержать отдельный домен с собственным сертификатом, который указывает на этот сервер. В публичном хосте входящего укажите этот домен и порт 443, чтобы клиентам выдавался публичный адрес. Naive QUIC на UDP в этот режим не входит.
- Если вы меняете внутренний порт или SNI NaiveProxy, повторно примените настройки HAProxy. Публичный TCP 443 должен принадлежать HAProxy.

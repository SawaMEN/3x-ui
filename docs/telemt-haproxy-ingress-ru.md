# Общий HTTPS-вход на TCP 443

В настройках Telemt WEB выберите **HAProxy → Общий HTTPS-вход на порту 443**. Режим доступен и в отдельной настройке Telemt WEB, и во входящем MTProto с включённым WEB Proxy.

| Сервис | Пример публичного адреса | Внутренний адрес |
|---|---|---|
| Панель | `https://web.example.com/admin-path/` | `https://127.0.0.1:8443/admin-path/` |
| Подписка | `https://web.example.com/sub-path/<id>` | `http://127.0.0.1:2096/sub-path/<id>` |
| Telegram WEB | `web.example.com:443`, путь `telegram/web` | Локальный порт, выделенный Telemt |
| Заглушка | `https://web.example.com/` | Тот же локальный Telemt |
| NaiveProxy HTTPS | `naive.example.com:443` | TLS на `127.0.0.1:9443` |

- У панели должен быть TLS-сертификат и отдельный путь входа. TCP 443 нужно освободить для HAProxy. Панель подключается к существующим внутренним портам через loopback. Если слушатели сейчас привязаны ко всем адресам, их привязка сохраняется.
- Если публичный URL подписок пуст, панель использует домен Telemt WEB. Для пустого пути Telemt WEB используется `telegram/web`. Проверка перед включением покажет пересечения путей.
- Для подключения NaiveProxy выберите локальный TCP-входящий из списка. Его поле SNI должно содержать отдельный домен с собственным сертификатом, который указывает на этот сервер. Панель автоматически добавит публичный адрес с портом 443 в подписки. Naive QUIC на UDP в этот режим не входит.
- При изменении порта или SNI NaiveProxy панель обновит маршрут HAProxy автоматически. Публичный TCP 443 должен принадлежать HAProxy.

# Проверка входящих протоколов в каскаде

Ветка: FIXX. Проверка касается прохождения трафика через маршрутизатор панели
и выбранный outbound, включая outbound из подписки. Наличие протокола в меню
не означает, что его отдельный сервер использует маршрутизацию sing-box.

## Все типы входящих подключений панели

| Тип                  | Путь через исходящее подключение                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| VLESS, VMess, Trojan | Нативный маршрутизатор; проверена генерация маршрута к outbound подписки                                                                                     |
| Shadowsocks          | Нативный маршрутизатор; проверена генерация маршрута к outbound подписки                                                                                     |
| HTTP, Mixed          | Нативный маршрутизатор; HTTP CONNECT переносит TCP; UDP зависит от SOCKS/протокола клиента                                                                   |
| Hysteria 1/2         | Нативный маршрутизатор; отдельный Hysteria 2 также подключается через SOCKS-мост                                                                             |
| TUIC                 | Нативный маршрутизатор; восстановлено определение доменов/протокола перед выбором маршрута                                                                   |
| NaiveProxy           | Нативный маршрутизатор либо SOCKS-мост отдельного сервера; транспорт клиента и поддержка UDP проверяются отдельно                                            |
| AnyTLS, Snell        | Нативный маршрутизатор; проверена генерация маршрута к outbound подписки                                                                                     |
| ShadowTLS            | Внутренний прокси сохраняет тег входящего подключения; транспорт ShadowTLS сам не выбирает выход                                                             |
| MASQUE               | Нативный endpoint, подключённый к общему маршрутизатору                                                                                                      |
| TUN                  | Нативный маршрутизатор; создание интерфейса дополнительно требует прав ОС                                                                                    |
| AmneziaWG            | Восстановлен отсутствовавший локальный SOCKS-мост: TCP и UDP, авторизация по имени клиента, исходный тег входящего подключения                               |
| MTProto              | Через SOCKS-мост при включённом `routeThroughXray`; без этой настройки отдельный сервер выходит самостоятельно                                               |
| Mieru                | Все IP и домены направляются через SOCKS-мост ядра; учёт клиентов остаётся у Mieru                                                                           |
| TrustTunnel          | `forward_protocol.socks5` направляет TCP/UDP в ядро; учёт клиентов остаётся у TrustTunnel                                                                    |
| Pingtunnel           | `forward` автоматически подключён к SOCKS-входу ядра; выход выбирают общие правила панели                                                                    |
| FPTN                 | Отдельный контейнер со своей сетью; общий outbound панели не используется                                                                                    |
| OpenFlux             | Отдельный процесс в роли exit; общего моста к outbound панели нет                                                                                            |
| Sudoku               | Официальный сервер из SUDOKU-ASCII/sudoku; прямой выход с сервера, без маршрутизации и каскада ядра панели                            |
| VK TURN Proxy        | Внешняя цель подключена через UDP-вход ядра; локальная WireGuard/Hysteria2 цель получает отдельный вход с тегом VK для маршрутизации расшифрованного трафика |
| WireGuard            | Локальное завершение туннеля через нативный userspace endpoint, включая цели VK TURN; клиенты и их отключение сохраняются                                    |
| Tunnel               | Legacy-тип по-прежнему не реализован в общем переводчике                                                                                                     |

## Исправления

1. Отключённые правила больше не включаются при переводе Xray routing в sing-box.
2. TUIC сохраняет sniffing для доменных и протокольных правил.
3. Обновление подписки сохраняет порядок подключений и первый outbound.
4. AmneziaWG получает loopback SOCKS-мост после применения нативного шаблона.
   Имя пользователя и пароль совпадают с embedded relay; отключённые и
   исчерпавшие квоту клиенты не добавляются. Конфликты тегов и портов отклоняются.
5. Учёт полезного трафика AmneziaWG выполняет core. Задание диагностики обновляет
   присутствие по handshake, без повторного добавления счётчиков устройства.

## Что проверяют тесты

- Генерацию конфигураций из БД для VLESS, VMess, Trojan, Shadowsocks, HTTP,
  Mixed, Hysteria 1/2, TUIC, Naive, AnyTLS, ShadowTLS, Snell и MASQUE с правилом
  к реальному объекту outbound подписки и блокирующим резервным выходом.
- Сохранение TCP/UDP-маршрута для TUN и AmneziaWG.
- Авторизацию SOCKS-моста AmneziaWG, отключённые/удалённые из квоты аккаунты,
  локальную привязку и конфликты портов/тегов.
- Отказ для неподдерживаемых legacy-listener типов.
- Существующие проверки MTProto, подписок, маршрутов и серверных процессов.

Это проверка кода, генерации конфигураций и доступных автоматических тестов.
Она не подтверждает сетевую доступность конкретных серверов пользователя или
полный обмен данными всеми клиентами/версиями протоколов.

## Ограничения исходящего подключения

TCP и UDP полезной нагрузки отличаются от TCP/QUIC транспорта самого VPN.
Даже входящий VPN на QUIC может передавать TCP через TCP-совместимый outbound.
Но UDP внутри туннеля требует поддержки UDP у выбранного outbound и всех
промежуточных звеньев. Обычный HTTP CONNECT или SSH не даёт универсального
UDP-выхода. SOCKS требует работающий UDP ASSOCIATE на удалённом сервере.
Не следует добавлять автоматический direct fallback для неподдержанного UDP:
это отправило бы часть трафика в обход каскада.

Входящие подключения, физически размещённые на удалённом узле, используют
маршрутизатор этого узла. Outbound центральной панели не переносится на узел
автоматически одним правилом для локальных подключений.

Проброс внешних портов AmneziaWG имеет обратное направление: внешний клиент →
внутренний адрес peer. Он намеренно идёт прямо в закрытый netstack туннеля,
а не через исходящий VPN-каскад. Его байты не входят в статистику SOCKS-моста;
для полного учёта такого проброса нужны отдельные счётчики.

## Интеграция дополнительных серверов

- Для Mieru, TrustTunnel и Pingtunnel ядро создаёт loopback SOCKS-вход
  с тегом исходного inbound. Применяются общий outbound по умолчанию и правила
  по входящему подключению, домену, IP и сети. Для Mieru/TrustTunnel имя клиента
  остаётся внутри отдельного сервера; общие правила по auth_user на этом мосту
  недоступны. Персональные квоты и статистику продолжает вести сервер протокола.
- Порты мостов детерминированы из ID; конфликты с другими мостами, слушателями
  и диапазонами Mieru останавливают публикацию некорректной конфигурации.
- Добавление, изменение, отключение и удаление сервера запрашивают обновление
  конфигурации ядра. Сохранённый нативный шаблон не может удалить мост.
- Для VK TURN локальная цель клонируется с исходными ключами/сертификатом,
  но собственными портом и тегом VK. Правило для VK не захватывает обычных
  клиентов исходной цели. Нативный WireGuard endpoint слушает UDP на всех
  интерфейсах: мост всё равно требует WireGuard-аутентификации, а его порт
  не добавляется в публичные ссылки.
- Sudoku устанавливается и обновляется из последнего стабильного релиза
  `SUDOKU-ASCII/sudoku` независимо от канала панели. Собственная сборка протокола,
  патчи и публикация бинарников удалены. Официальный сервер использует прямой
  выход: SOCKS-выхода для маршрутизации, каскада и счётчиков ядра панели у него нет.
  Ключи, клиентские ссылки и настройки сохраняются. Старую сборку заменяет
  обновление компонента; версия теперь соответствует тегу официального релиза.
- Старое поле Pingtunnel forward заменено общей маршрутизацией: его значение
  из сохранённых настроек не используется для обхода ядра.

### Дополнительные проверки передачи данных

- Mieru: настоящий серверный Mux/SOCKS из официальной библиотеки, четыре
  сочетания TCP/UDP транспорта и TCP/UDP полезной нагрузки, через SOCKS echo.
- TrustTunnel: официальный endpoint v1.1.0, HTTP/2 CONNECT и `_udp2`, через SOCKS echo.
- Sudoku: официальный релизный бинарник проверяется на генерацию ключей,
  валидацию конфигурации, запуск и передачу TCP, MUX и UDP-over-TCP.
- SOCKS-входы и локальные WireGuard/VK endpoints дополнительно проверены
  валидатором релизного ядра. Подключения к серверам пользователя и ICMP-обмен
  Pingtunnel в этой среде не проверялись.

Для Pingtunnel требуется версия 3.0 или новее: старые сборки могли использовать
forward только для TCP, продолжая отправлять UDP напрямую. Панель проверяет
версию перед запуском и передаёт forward отдельным CLI-флагом; несовместимая
сборка останавливается с сообщением об обновлении.

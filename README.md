# 3X-UI

<p align="center">
  <img src="./media/3x-ui-cyberpunk.svg" alt="3X-UI" width="460">
</p>

**3X-UI** — веб-панель управления модифицированным **sing-box** с веб-интерфейсом для управления inbound'ами, клиентами, подписками, маршрутизацией, статистикой и настройками сервера.

Интерфейс по умолчанию использует русский язык; английский также доступен. UI построен на Ant Design и адаптирован для desktop и mobile.

> [!IMPORTANT]
> Проект предназначен для личного использования и тестирования. Перед эксплуатацией на реальном сервере проверьте конфигурацию, сетевые правила, доступ к панели, TLS и остальные параметры безопасности.

## Быстрый старт

### Установка

Установочный скрипт находится в этом репозитории:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/SawaMEN/3x-ui/main/install.sh)
```

По умолчанию выбирается совместимый релиз из **SawaMEN/3x-ui**. Если последний
stable-релиз ещё не содержит миграцию на текущее ядро, скрипт сообщает об этом
и устанавливает опубликованную DEV-сборку. Явно заданная версия не заменяется.
DEV-сборки закрепляются за коммитом: архив, SHA-256 и меню берутся из одной сборки.
Установка старой версии поверх панели с новым ядром блокируется до замены файлов.

Для установки конкретной версии:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/SawaMEN/3x-ui/main/install.sh) v3.9.3
```

Для rolling dev-сборки:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/SawaMEN/3x-ui/main/install.sh) dev-latest
```

Установщик поддерживает Linux-архитектуры **amd64** и **arm64/aarch64**.

После установки управление панелью доступно через:

```bash
x-ui
```

Основные команды:

```text
x-ui              # меню управления
x-ui start        # запуск
x-ui stop         # остановка
x-ui restart      # перезапуск
x-ui status       # статус
x-ui settings     # текущие настройки
x-ui enable       # включить автозапуск
x-ui disable      # отключить автозапуск
x-ui log          # логи панели
x-ui banlog        # логи Fail2ban
x-ui update       # обновление
x-ui install      # установка
x-ui uninstall    # удаление
```

Результат установки сохраняется в защищённом файле:

```text
/etc/x-ui/install-result.env
```

### Обновление

Обновление панели:

```bash
x-ui update
```

Панель также предоставляет интерфейс для проверки системных обновлений и обновления управляемых панели и sidecar-компонентов, включая **Telemt**. Ядро **sing-box** входит в выпуск панели. Для системных обновлений поддерживается восстановление состояния панели после перезапуска во время применения обновлений.

Pingtunnel, TrustTunnel и Sudoku устанавливаются отдельно через менеджер компонентов. Sudoku загружается напрямую из официальных релизов SUDOKU-ASCII/sudoku, без собственной сборки панели. Его трафик выходит напрямую с сервера; маршрутизация, каскад и счётчики ядра панели к нему не применяются. Установленные дополнительные компоненты можно удалить кнопкой с корзиной: настройки сохраняются, а NaiveProxy и Hysteria 2 переключаются на sing-box. Перед удалением Pingtunnel, TrustTunnel или Sudoku необходимо отключить использующие их входящие подключения. В списке новых входящих подключений они появляются после установки; существующие записи можно редактировать и при отсутствии бинарника.

Для входящих NaiveProxy и Hysteria 2 панель автоматически использует установленный отдельный сервер, а при его отсутствии — встроенный sing-box. Сервер NaiveProxy загружается из [klzgrad/forwardproxy](https://github.com/klzgrad/forwardproxy/releases): это официальный Caddy-Naive; [klzgrad/naiveproxy](https://github.com/klzgrad/naiveproxy/releases) публикует клиентские бинарники. Установка сразу применяет конфигурацию, проверяет готовность процесса и откатывается при ошибке. Маршрутизация сохраняется через локальный SOCKS-мост; клиентская статистика Hysteria собирается через его локальный API. Caddy-Naive поддерживается на Linux/amd64, Hysteria 2 — на Linux/amd64 и arm64. Для неподдерживаемой платформы менеджер показывает пояснение вместо кнопки установки.

Официальный Hysteria не передаёт имя клиента в SOCKS-маршрутизацию: при наличии персональных правил `auth_user` установка отдельного сервера отклоняется, сохраняя sing-box. Ранее установленные бинарники не прерывают работу при несовместимых настройках: такие входящие остаются на sing-box, а менеджер показывает причину. Обновление уже установленного сервера сохраняет этот режим совместимости; проверка новой установки не затрагивает другие протоколы. Правила по inbound и адресу назначения работают через мост. Переключение также отклоняется, если требуется исходный IP клиента: для таких правил и клиентских IP-лимитов следует использовать sing-box.

## Возможности

- Управление единственным ядром **Sing-box**.
- Создание и управление inbound'ами и клиентами.
- Поддержка **VMess, VLESS, Trojan, Shadowsocks, WireGuard, Hysteria, HTTP, Mixed, Tunnel, TUN, MTProto, AmneziaWG, TUIC, Naive, Mieru** и **vk-turn-proxy**.
- Локальное управление отдельным sidecar-сервисом **Mieru**; его конфигурация и процесс синхронизируются с активными inbound'ами.
- MTProto через встроенный **Telemt** (отдельный управляемый процесс на каждый inbound).
- **VetroffProxy**: установка и обновление готового Linux AMD64/ARM64 бинарного релиза из карточки компонентов. После установки доступен протокол `vetroff` с пользователями и ссылками `vetroff://`. По умолчанию компонент отсутствует. Устанавливается полный NSS/Necko runtime; временный архив удаляется. Удаление компонента очищает runtime и оставшиеся временные загрузки, сохраняя настройки подключений. Сборка на сервере не требуется. Автоматически подбирается действительный TLS-сертификат панели/домена; доступны ручные пути, SPKI pin, все восемь транспортов, XHTTP, HTTP/3, UDP, egress, Bond/discovery, резервные серверы и нативные политики пользователей. Настройки подключения переносятся в raw/base64 подписки. Локальные параметры клиентского движка не входят в формат `vetroff://`. Статистика трафика и лимиты панели для этого протокола пока не поддерживаются.
- Лимиты трафика, срок действия, IP/HWID-лимиты и статистика.
- Поддержка клиентских подписок, JSON/Clash-экспорта и внешних ссылок/удалённых подписок, привязанных к клиенту.
- Экспорт профилей Amnezia VPN, QR из нескольких частей, наборы совместимости AWG и клиентские параметры обфускации.
- Нативный AWG outbound в ядре и защищённые метрики Prometheus. См. [настройку Amnezia](docs/amnezia-integration.md).
- Управление исходящими подписками и их автоматическим обновлением.
- Управление узлами, синхронизация конфигурации и просмотр системной статистики.
- SQLite по умолчанию и PostgreSQL в качестве альтернативной БД.
- Интеграции с Telegram, Discord и Fail2ban.
- Темы: светлая, тёмная, ultra-dark, colorful и blue-gray.
- Адаптивный интерфейс для desktop и mobile.
- Русский интерфейс по умолчанию, английский — дополнительный язык.

## Поддержка ядер

### Модифицированный Sing-box

Панель запускает собственную модифицированную сборку Sing-box (Hiddify-core) и показывает её как **sing-box**. При каждой сборке панели (GitHub Actions или Docker) скачивается готовый бинарник из **последнего стабильного релиза** [SawaMEN/hiddify-core](https://github.com/SawaMEN/hiddify-core/releases/latest) (`releases/latest`, без prerelease и draft). Исходники ядра в панели не компилируются. Архив и файлы ядра проверяются по SHA-256, а версия и ревизия сверяются с прилагаемым `target.json`. В одном релизе используются согласованные сборки AMD64/ARM64. Если проверка не пройдена, сборка панели останавливается. Уже установленная панель обновляет ядро вместе с новым выпуском панели (`x-ui update`, а для dev-канала — `x-ui update-dev`). Отдельного загрузчика Xray или обычного Sing-box нет. Форматы клиентских подписок Xray и sing-box сохранены.

Установленные панели переходят через offline-миграцию с резервной копией и проверкой запуска. Старые бинарники удаляются из рабочей установки после успешной проверки. См. [этап 10](docs/reports/hiddify-core/hiddify-core-stage-10-verification.md) и [инструкции миграции](docs/reports/hiddify-core/hiddify-core-stage-9-verification.md).

Периодический сбор traffic statistics оптимизирован для больших наборов соединений:

- состояние трафика отдельных соединений не хранится в памяти панели между опросами;
- для traffic polling используется облегчённый protobuf-декодер;
- в traffic polling не декодируются поля соединения, которые не нужны для статистики;
- события закрытых соединений не удерживаются панелью после обработки.

При этом **RSS процесса sing-box и RSS панели — разные величины**. Сам sing-box может потреблять дополнительную память в зависимости от количества соединений, DNS-кэша, конфигурации маршрутизации и других факторов.


## Язык интерфейса

Русский (`ru-RU`) — основной язык интерфейса.

Английский (`en-US`) — дополнительный язык.

Если язык браузера не поддерживается, интерфейс использует русский.

## Структура исходников

- `internal/` — сервер панели, протоколы, база данных и подписки.
- `frontend/` — интерфейс панели; сборка встраивается в Go-бинарник.
- `deploy/` — конфигурации развёртывания; корневые скрипты сохраняют совместимость установщика.
- `tools/` — генераторы, проверки и вспомогательные скрипты.
- `docs/` — документация; `docs/audits/` — отчёты аудита, `docs/reports/hiddify-core/` — история проверок миграции ядра.

Для разработки см. [CONTRIBUTING.md](CONTRIBUTING.md) и [frontend/README.md](frontend/README.md).
